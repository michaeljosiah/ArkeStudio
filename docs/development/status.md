# Bounded implementation status

Checked against source on 5 September 2026. This register clarifies areas that had misleading blanket descriptions; it is not a complete roadmap or a passing-test report. Keep entries current when their cited behavior changes. Capability specs remain the detailed requirements.

| Area | Status | Evidence and limit |
|---|---|---|
| Proactive recovery and Studio assistant (#2194) | Partial, 27 October 2026 | PR #2197 implements managed-service recovery/reviewed stopped-service retries, scoped storage observation/admission, private Studio transport/dialog/history/local dictation, and reviewed fixed-preview cleanup with witnessed reconciliation and default-off standing maintenance. Full native model-route/spend/privacy/cleanup qualification, attachments/read replies/effort, other repairs/cache classes/write owners, remaining SDK/Ming health/action integration and matched turn-239 visual acceptance remain unfinished. The default inference route refuses without qualified host proof. See SPEC-061/062 and the current code map. |
| Steering and next-message queue (#1138) | Persistence foundation, 2 October 2026 | The [input journal, replay, recovery and queued-turn entry point](conversation-inputs.md) are implemented. Composer and transport admission, the dispatch scheduler, full runner/approval integration and verified native steering are outstanding. No adapter advertises native steering. |
| Episodes | Partial | Client [App.tsx](../../packages/client/src/App.tsx) routes episode detail/chat screens; [episode-create.test.ts](../../packages/coordinator/test/productions/episode-create.test.ts) covers episode creation. This does not establish a complete season-production or audience-publishing workflow. See SPEC-012. |
| Local voice protocol | Implemented client | [voice/src/index.ts](../../packages/voice/src/index.ts) contains sidecar schemas and client behavior. Runtime readiness and supported operations still depend on setup and available engines; this is not a claim that every planned voice feature is delivered. See SPEC-011. |
| World ownership | Bounded desktop checks accepted | ADR-002 accepts local disk identity checks and ownership-loss handling; hosted leases and atomic fencing remain proposed. Local checks do not establish cross-machine concurrent ownership. |
| Host/cloud foundation | Designed / incomplete integration | SPEC-025 describes the host ports; a named cloud entry in the product is not evidence of completed sync/collaboration integration. |

For other capabilities, read the relevant spec's current implementation notes and follow its source/tests. Historical architecture reviews may describe risks fixed by subsequent work; check the linked decisions and operational rules before applying their recommendations.

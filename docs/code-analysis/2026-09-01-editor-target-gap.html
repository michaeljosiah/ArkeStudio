The Short Version

The target is much more than a new layout.

It combines the asset library, preview, timeline, clip settings, take choices and Arke assistant in one screen. It also expects normal timeline editing, mixed audio, subtitles, undo, and more export choices.

Arke already has strong foundations: accepted takes, visible gaps, real file storage, crash-safe saves and local export. We should keep those parts.

Three implementation issues must be solved before the target editor can be trusted:

  1. The current story cut does not save clip order. The new editor must save Arke's first assembly as an editable timeline that people can always override.
  2. The current preview is silent and does not show every picture placed on the timeline. Export can therefore look and sound different from preview.
  3. Episode and music-timed exports can silently leave out clips that are visible on the timeline.
Most of the product direction is now clear. The story guides generation and seeds the first edit, but it does not lock the editor. Plain recommendations for audio and subtitles are included below for review.

What The Target Editor Is Trying To Be

The downloaded file is a design prototype. It shows the intended workflow, but it is not a working media editor. It uses still images instead of real video, has no real audio mix, does not save work, and does not produce an export.

What not to copy from the prototype

  • It is fixed at 1400 by 880 pixels and does not adapt to smaller windows.
  • Most controls are clickable text or boxes instead of accessible buttons and menus.
  • Several actions are broken, including take switching, one Arke edit, keyboard playback and adding selected shots.
  • Upload and Export look active but do not do the work.
  • Its waveforms, playback, audio and subtitles are only visual examples.

Agreed Decisions And Recommendations

The agreed choices describe how the editor should behave. Audio and subtitles include recommended defaults based on common editing workflows.

1. The story starts the edit but never locks it

During generation: the story controls which shots are made and their default order. This is where tighter controls belong.

After generation: Arke places the available shots into the editor as the first cut. That saved timeline then controls the finished film.

  • A human can always move, split, duplicate, replace or delete a clip.
  • The UI may warn that the edit no longer follows the story, but it must never block the change.
  • A later story change must not silently overwrite manual timeline edits. Arke can offer an update as an approval request.
  • Standalone productions use the same editable timeline, simply without a story-based first assembly.

Saved result: generation follows the story; delivery follows the editor timeline.

2. Use the target's track model

Today: placed clips use numbered, untyped lanes. A separate unused model describes dialogue, score and ambience.

Decision: use named Picture, Dialogue, Ambience, Music and Subtitle tracks. Each track has a stable ID, order, name, type, mute setting and clips. The current score concept becomes music.

3. Store time as video frames

Today: most timeline positions are decimal seconds. Story, episode and music-timed cuts use different clocks.

Decision: every production has a frame rate, such as 24, 25 or 30 frames per second. Save clip positions and lengths as whole frame numbers and display them as hours:minutes:seconds:frames.

This is the normal video-editing model. It makes cuts exact and makes handoff to other editors much easier. A production can default to 24 frames per second, while allowing another rate when the production is created.

4. Keep speech clear by lowering background sound

Today: the editor preview is silent. Export can combine sound, but there are almost no controls for how loud each part should be.

Recommended behavior:

  • Dialogue and narration are the most important sound.
  • When someone speaks, music and ambience become quieter by 9 dB by default. In plain terms, this is a strong reduction, but the background remains audible.
  • The background fades down quickly instead of jumping, then returns smoothly after the speech ends.
  • The user can turn this behavior off or change how much quieter the background becomes.
  • Every clip has a simple volume control. Every track has Mute (turn it off) and Solo (hear only that track).
  • Preview and export must sound the same, and the final mix should prevent harsh distortion when several sounds overlap.

This automatic lowering is commonly called ducking. It is a normal starting point for dialogue-led video, but it remains editable rather than forced.

5. Every completed editor action can be undone

Today: saves are crash-safe, but completed Cut edits have no Undo or Redo.

Decision: one drag, one menu action, one take switch or one accepted Arke request equals one undo step. Redo reapplies it. Undoing a take switch changes the selected take back but does not erase the review history.

6. Arke can request approval for any editor action

Decision: Arke can prepare any action a human can perform in the editor. The request appears in chat with an Accept action and a plain summary of what will change.

  • Accept applies the changes immediately to the editor.
  • The full accepted request is one undo step.
  • Reject changes nothing.
  • Where useful, the timeline shows the proposed result as ghost clips before acceptance.
  • If the timeline changed after Arke prepared the request, Arke must update the request and ask again instead of applying an old edit.

7. Store subtitles as editable timed text

Today: there is no saved subtitle cue model and no subtitle export.

Recommended model: each subtitle item contains the words, start frame, end frame and optional speaker. A subtitle track also stores its language and a simple shared appearance.

  • Subtitles can be imported from SRT or VTT files.
  • Speech-to-text can create the first draft.
  • People and Arke can edit the words and timing.
  • Support more than one subtitle track so a film can have different languages.
  • Export choices are: none, printed onto the video, a separate subtitle file, or both.

The editable timed text is the saved original. Text printed onto an exported video is only an output, not the source.

8. Every export includes the visible tracks

Today: production-wide export includes placed lanes. Episode and music-timed export do not.

Decision: support visible picture, dialogue, ambience, music and subtitle tracks in every export mode. Production, episode and music-timed exports must all use the same timeline contents and settings.

Current labels that are misleading

  • Review cut says "timecode", but export does not add timecode.
  • Social excerpt says "captions", but export does not add captions.
  • Social excerpt is not an excerpt; it currently renders the full cut in a vertical frame.

These labels should be corrected now, before the larger editor work.

Recommended Build Order

1. Fix current export truth

Stop episode and music-timed exports from dropping visible clips. Remove unsupported timecode, captions and excerpt wording. Clearly state that current preview excludes placed media and sound.

2. Build the agreed timeline foundations

Add the story-seeded editable timeline, target track types, frame-based time, subtitle data, undo history and migration from current seconds and numbered lanes.

3. Build the new shell in read-only form

Put library, preview, timeline, Inspector and Arke in one screen. Reuse existing data and actions. Add pane collapse, focus order and keyboard access now.

4. Add editing and undo

Add move, trim, split, duplicate, delete, ripple and track actions. Warnings can explain when an edit leaves story order, but they never block it. Make every action one safe save and one undo step.

5. Make preview and export use the same rules

Add picture compositing, mixed audio, real waveforms and subtitles. Speech lowers background sound by the editable default. The browser preview and every FFmpeg export mode must use the same tracks and settings.

6. Add takes and Arke to the Inspector

Reuse the current take acceptance flow. Let Arke request approval in chat for any editor action. Accept updates the editor immediately and creates one undo step; Reject changes nothing.

7. Add professional delivery

Add codec, size, subtitles, audio outputs and saved presets. Add OTIO only after the final time, track and export rules are stable.

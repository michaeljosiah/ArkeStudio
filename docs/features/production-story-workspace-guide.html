The production development workspace

From a world you have
to a scene you can shoot.

Arke already holds your world: characters, places, canon, a look. It already knows how to turn a finished shot into video. This is the part in between — deciding what a film or a season is about, breaking it into episodes and scenes, and writing the script the shots will cover.

Status · part built, and the built part now runs end to end

The pictures below are the real frames from the design master, turns 43–53, embedded rather than screenshotted, so what you see is exactly what was specified — including turn 78’s rename, since superseded by turn 89 (the rail item reads Production Chat), and turn 83’s reconciliations. That is not the same as what shipped, and this document now says which is which: every section that has been built carries an As built note naming the differences, and the sections without one are still drawings.

The short version, verified against v0.5.30 on 2026-08-20 by driving the installed app: creation, day one, Production Chat and its details, scenes, dispatch, plans, the cut and export are built — a world now reaches a rendered film without leaving Arke, which is further than this guide was originally written to go, and the last act is added at Getting it out. Script, Coverage and the Board are not built: those three frames remain the specification and nothing else. The companion production-story-workspace-brief.html tracks build state issue by issue.

What it is

Four things to decide, in order.

A production borrows from a world. It never copies it. Change a character once and every production sees it. What this feature adds is the layer of decisions that belong to this film and nothing else.

Season

What changes this time

The question it answers, how it ends, the arcs running through it, and how it looks. A short film has the same thing with fewer parts.

Episode

One promise to the audience

How it opens, where it turns, how it closes. A hook and a cliffhanger. Then the scenes that get it there.

Scene

What happens and is said

The script, then the shots that cover it. This is where the existing pipeline picks up.

One rule explains every layout here. If a screen is for writing one thing, the conversation sits on the left and a 470px draft panel on the right. If a screen is for comparing things to each other, it takes the full width and the conversation shrinks to a single row at the bottom. That is why Episodes and Arcs get the whole page, and Season, Direction and Script keep the panel. The test is not how important a screen is. It is whether you need to read rows against each other.
Starting

Creating a production opens it.

Three screens before there is anything to write in. Pick what you are making, pick what kind of it, then start writing.

Step one · what are you making?

Format is the first choice and the structural one. Story, video or stills. It decides which screens exist for the rest of the production, and it is the only choice here that does: a story gets chapters, stills gets a contact sheet, video gets scenes, shots and a cut.

Nothing is copied out of the world. Whichever you pick, the production shares the same characters, places and canon, and picks up changes to them as they happen.

Step two · what kind of video?

Three kinds, each with a picture. Under them, four settings: the frame, how many episodes, how long each one runs, and how it ends.

The kind only sets the starting numbers. A Microdrama is still a Video production, with the same scenes, shots, takes and cut as a short film.

The four settings are dropdowns, not labels. That is deliberate: a number you cannot tell is editable is a number nobody edits. Change them here or later.

If a format has only one kind, this step does not appear at all. A question with one answer is a toll.

As built · v0.5.30 Both steps ship, and both frames are now what runs. Creation was one page until 2026-08-20: it revealed the kinds inline and created from step one, so the kind and the numbers that differ between kinds were settled by a button that said Create production, and EPISODE LENGTH was never asked at all. Step three · the empty production

The button says where it goes — Create and open it — and it lands you on a page with one job: start writing.

There is a heading, a box to type in, and two ways in. Write the first scene goes straight to something you can shoot. Shape the whole thing first decides what it is before any of it gets written.

Nothing here lists what the world contains. The production is already inside the world — the rail says which one — so announcing it again would be noise. Typing changes nothing until you accept.

An earlier version of this page suggested things to write — open questions from the canon, and scenes another production planned but never shot. Those are gone. They guess at a way of working that nobody has done yet. If the plain page turns out to be too quiet, they come back.

The workspace

A conversation next to a draft.

Production Chat — drawn here as Development, renamed by turn 89 — works the same way as the two conversation screens Arke already has. You talk on the left. The draft builds on the right. Nothing is written until you turn it into a proposal.

  • Talking writes nothing. Every reply ends with a receipt saying so.
  • Changes are marked on the field they affect, with the current text below.
  • One button turns the draft into one proposal for one file.
  • Accepting happens on the proposals screen, like every other change in Arke.
As built · v0.5.30 It ships as Production Chat (turn 89): “Development” named a phase of filmmaking rather than a thing on a screen, and this is World Chat with a production for a subject. The details it settles are a separate rail item — Season for an episodic production, Overview otherwise (turn 88) — whose tab strip is Season, Arcs and Direction, with Episodes appearing only once episodes exist — exactly the rule this section promises, honoured in the code rather than by a greyed-out tab. The Season view shows the Series engine as a read-only card naming what it governs, and a season with nothing decided says so in words: “The season question · Not asked yet”, “How it ends · Not decided yet”. What has not been exercised is the marked-up draft panel above: a production whose conversation has proposed changes to a written overview.
The season

Four views of the same season.

Season, Episodes, Arcs and Direction. A production with no episodes shows three, not four with one greyed out.

Episodes takes the whole page because the point is comparing them — whether episode five earns its place between four and six. You cannot answer that if you can only see five of seven. Unwritten episodes are dashed tiles with a sentence in them, so the shape of the season is honest before it is written.

A lane is a thing that changes, not a character. Maren appears in two of the rows above and is neither of them. The finale column is where you find out whether an arc actually lands.

What a season inherits

The Season view shows the Series engine as a read-only card, and says that editing it opens the Series. A field that quietly edits two seasons at once is exactly the kind of drift the world model exists to stop. Direction works the same way: it shows the world look first, then the lines this season narrows against it, and says plainly that no other production moves.

The episode

A promise, then the scenes that keep it.

You open an episode from a card on the board. The panel shows what the episode promises, and then the scenes, in order. There is nothing in between.

The promise is three lines: how it opens, where it turns, how it closes. Anything the conversation just changed is marked new.

Under it, the scenes. Each one is a number, a title, one line saying what happens, and its state — accepted with a shot count, or written but not yet scripted. A scene with no script says so and you click it to write one.

There used to be a layer between the two, called beats: named units of change that scenes were cited against. It bought a many-to-many map that a five-scene episode does not need, and it cost a whole second screen to explain. It is gone. A script belongs to a scene and to nothing above it.
The scene

Script first. Shots second.

A scene is written before anything decides how to film it. Then shots are added, and each one says which parts of the script it covers.

Block ids are given once and never renumbered. Insert a block between A03 and A04 and it becomes A08. That looks odd in a list, and it is the whole point: renumbering would silently change what every shot is pointing at.

Dialogue lives in the script block. The shot points at it rather than repeating the line, so there is only ever one copy of what is said.

When the script changes

Editing a covered block does not break anything. The block keeps its id, and any shot pointing at it is marked covers text that changed — out of date, not broken. Cutting a block leaves the shot in place marked covers nothing. It is kept, not deleted, because you framed and timed it and that is not Arke's to throw away.

Splitting a block is not a special case. It is an edit plus an insert, and you have already seen what both do. The one thing Arke cannot work out is which half a shot was for, so it asks.

The board

The board is the visual read and the place a scene gets paid for. Every shot in scene order, at the shape it will be watched in. A 9:16 production boards portrait, so the frame chosen back at step two is visible here rather than discovered at the end.

Each panel carries its own price, and the whole scene's total sits at the bottom next to the button that spends it: Generate 4 shots · $5.46. Nothing has been sent.

  • A gap is a panel. A shot with no frame keeps its place, number, duration and coverage, because a half-generated scene still has to read in order.
  • Warnings sit in one bar and none of them block. Script with no shot, a character who is still a sketch. Each names the thing it is about, and the bar offers to add the missing shot.
  • Where a length rounds up, the panel says both. A provider only makes a few fixed lengths; ask for 3 seconds on a route whose shortest is 4 and you pay for 4. It says so here, not on the invoice.
  • Compiling is free and local. The same scene state always makes the same board and files nothing. Exporting files one artifact, which is why it is a separate button.
  • Staleness is per panel. A script edit dims the panels it actually touched and leaves the rest alone.

This board is not what gets sent to a model. It is editorial, it may hold placeholders, and the provider-ready storyboard is compiled separately at dispatch. Two artefacts, one shot plan.

Clicking a panel

Select a shot and it opens beside the board. The prompt is a field you can type in, not a printed block. The model, the size, the length and the references are the same dropdowns as everywhere else.

  • An edited prompt says it was edited, and offers the assembled one back. Worth knowing, because the assembled version keeps up with a world that moves and a hand-written one does not.
  • The price stays on the screen — this shot, and the whole scene — so there is nothing else to visit before spending.
  • Warnings name the thing. A sheet that is still a sketch, a reference that will not fit the route.
There used to be a separate screen between the board and the money, called the plan. It showed the same four shots, the same coverage and the same prices, one screen earlier. It is gone, and what it was right about — the warnings, the uncovered blocks, the scene total — moved onto the board. Nothing on these screens blocks you: every warning names the specific block or shot and lets you carry on.

A scene in the app is a title, a status and a list of shots.
  • The data model is there ahead of the screens. Scene records carry script blocks, and a shot can cite the blocks it covers along with a digest of the text at citation time, so “covers text that changed” is a derivation waiting for somewhere to be shown. The writing surface is what is missing, not the vocabulary.
  • What did get built is the money moment, elsewhere. It offers per-shot and whole-scene prices side by side, and (since SPEC-024) a durable plan that chains each pass behind the previous pass’s last frame. Same promises, different address.
  • Read these four frames as the specification they are. Nothing in them has been contradicted by what shipped — it simply has not been drawn in code yet.
Getting it out

From accepted takes to something you can send.

This guide originally stopped at the first spend, because that was where the design stopped. The rest of the pipeline has since been built, so it is written down here: a shot becomes a take, an accepted take becomes part of the cut, and the cut becomes a file. These two frames are older than the rest of this document — turns 24 and 25, drawn before the workspace was — and they are what shipped.

Accepting a take is what puts it in the cut

A dispatch lands a take beside its shot, and nothing else happens: a take that arrives is a candidate, not a decision. Accepting one is the act that binds that clip to that shot, and the cut is a projection over those decisions — not a document you assemble.

Because it is a projection, there is nothing to keep in sync and nothing to rebuild. Accept a better take for shot 3 and the cut simply reads differently. The screen says so at the bottom, in the plainest terms it can: the cut recomputes from shot selections, so restoring an earlier cut means restoring the selections that produced it.

The header counts coverage the same way the coverage view does — 13 of 15 shots covered · assembled from accepted takes only — and the bar underneath names the gaps in seconds. A scene with no takes yet holds its place on the timeline; the film is honest about its own holes before anyone watches it.

Export is a render, and the cut stays the source

Exporting does not consume the cut or freeze it. It renders one file at one preset and files it under the production, which is why the screen is headed renders of the cut — the cut itself stays the source. Delivered exports stay listed with what they were: format, size, what was burned in, and when.

As built · v0.5.30 Both screens ship, and on 2026-08-20 a scene was taken from written to rendered without leaving the app: two shots dispatched as a chained plan, both takes accepted, a cut reading 19s · 3 of 3 shots covered · 0 gaps, and a 1080×1920 h264 file on disk under exports/. The differences from the frames are in the presets, not the shape.
  • The presets name real sizes. Review cut renders mp4 1280×720, Master 1920×1080 · clean, Social excerpt 1080×1920 · 9:16 · captions. The drawing’s ProRes 4K master and its “pick a scene” step are not built; a social export takes the whole cut.
  • Episodes became deliverables. A row the frame never had sits above the presets — Episodes · each its own deliverable, with a season-wide export — which is the “not designed yet” item at the foot of this guide, since designed and built.
  • Rendering says what it costs, and it is nothing. The frame hedges with “when the machine allows · est. 4 min”; the built screen says renders locally · no provider call, which is the more useful fact.
  • A second button files the whole world as a folder that reopens elsewhere — history kept, caches and locks left behind.
The boundary

What can actually change things.

These rules are inherited from the rest of Arke. This feature adds screens; it does not widen what an agent may touch.

  • Conversation proposes, never writes. A reply can read the world and suggest changes. It cannot write a file, accept a proposal or spend money.
  • The accept gate is the only path. Every authored change becomes a staged proposal holding whole files, checked against the version it was drafted from.
  • Accepting a scene creates shots and dispatches nothing. Money moves only at an explicit dispatch, with the estimate shown first.
  • World facts cross over separately. If a production conversation turns up something true of the whole world, it becomes a world change and is reviewed on its own.

A day in the life

Thursday, with The Undersong.

One morning making a seven-episode Microdrama in a world that already exists, including the part where the season is wrong. Each step says what reached disk. Written as though it were built.

09:38 · creating

A world she has, an idea she half has.

New production, Video, then Microdrama series. Seven episodes, 45 to 75 seconds, vertical. She types the idea the way she would say it out loud: a bell-ringer on the late watch starts getting answers back.

On disk: production.json and series/bell-watch.json created. One line in changes.jsonl. Nothing generated.
09:39 · arriving

Day one, and the world came with it.

Six faces, three locations, the tone, art direction v3. No briefing and no seed rails — an empty production is a place to start writing (turn 53). She opens Production Chat and starts on the season.

On disk: nothing. Arriving only reads.
09:52 · the season

The engine is not the question.

She says the season is about who is answering, not whether her mother is alive. The reply separates them: the nightly answer is the Series engine and season two needs it. What changed is the season question and its ending.

On disk: nothing while talking. On accept, season.json written, old version to .history/. The Series engine untouched — that needs its own accept.
10:14 · the board

Seven cards, and two of them are lying.

Five have hooks, four have cliffhangers. Episode three says NO ENDING YET. Episode six is a dashed tile with one sentence, which is honest.

On disk: nothing. The board is a view over the episode files.
10:26 · the episode

It opens well and stops.

She opens episode three and says the street is there but the house numbers are wrong. That becomes the turn, and gives the episode a closing state it did not have. Two new scenes appear, neither with a script.

On disk: on accept, episodes/03-the-missing-night.json with its promise and five scenes in order. Two have no script, and say so.
10:41 · the scene

A scene with no script offers to get one.

She clicks scene 11, whose one line reads Maren rings, and the answer comes from inside it. That line is the brief. Seven script blocks come back, with the canon it checked named. She accepts, then adds four shots that cover five of them.

On disk: scenes/11-the-answer-from-inside.json with its blocks and shots. No money spent.
10:58 · the arc that never lands

The grid says what the board could not.

Three lanes. Two turn and pay off. Odile's has a setup, a turn in episode five, and NO PAYOFF in the finale column. She has been believed and disbelieved and the season never decides which.

On disk: nothing yet. Lanes live in season.json; the missing payoff is worked out, not stored.
11:20 · the first spend

Four shots, priced before any of them run.

She opens the board and gets the whole bill: four panels in order, a price on each, $5.46 in total. Two things are flagged and neither blocks — two blocks have no shot, and Odile is still a sketch. Shot 3 says it will bill as 4 seconds because 3 is shorter than the route makes. She clicks shot 2, reads its prompt, shortens one line, sees that one of its three references will be dropped and why, and sends all four.

On disk: a job in queue/jobs.jsonl before any network call, then the file into incoming/, then a take. Accepting writes selections.json and reviews.jsonl together. The scene file does not move.
11:48 · the film

Two clips, one of them opening on the last frame of the other.

She accepts the take for each shot. The cut is already there when she opens it — nothing to assemble, because it is a projection over the takes she just chose — and it reads 3 of 3 shots covered · 0 gaps. She exports the social preset and watches the file: the hall, the light coming on over the chalk circle, and then the same hall from the same angle as dust falls through the beam, because the second clip was made from the last frame of the first.

On disk: a boundary frame in artifacts/, the second job carrying it as its first frame, then exports/bell-watch-social-excerpt-….mp4. Nothing was uploaded to make the file — the render is local.

Limits

What this does not do.

On purpose

No branching and no graph. A season is a sequence, and stays one — branching belongs to the Interactive Video kind, where a choice routes directly to the next scene, with no variables, conditions or hidden state, and validation reports named findings rather than a score. No editing the world from a production conversation. No generating from anything unaccepted.

Not designed yet

A Series view for when season two exists.

There is no after view. You can read and edit a shot's prompt before it runs, but once a take exists there is no screen that shows what was actually sent. Part of that is a gap in the data: a take records the canon version, the sheet versions and the art direction version it was made from, but not which reference images travelled. That cannot be worked out later, because the world has moved on. So the record has to start being kept before the screen can exist.

Since built · v0.5.30 Two items that stood here have been designed and built, and are struck from the list rather than left to mislead:
  • Saving a plan. This said the numbers were worked out fresh each time and nothing wrote down what you intended to send. SPEC-024 made a plan durable: an immutable record with a pre-allocated key per pass, an append-only journal beside it, and a state folded from the two. A review-gated plan stops at each pass and names the price of continuing; a pre-authorized one runs the chain to the end. Cancelling is an event like any other and survives a restart.
  • An episode-aware cut and export. This said seven episodes were seven deliverables while the cut was one timeline. Exports now carries an episode row and a season-wide render.
The after view above is still missing and still worth wanting — though a dispatched pass now records the route it took, the exact parameters sent and the references that were dropped, so more of the record it would need is being kept than when this was written.

Unresolved

Two step-two screens for Video existed when this was written: this feature's kind step, and an older one offering Watch, Choose and Interact. The Scope has since reconciled them — Watch is plain Video, Choose is the Interactive Video kind, Interact is deferred — so the older screen retires and the kind step here is the survivor. What remains untested: a season of twenty is the first thing that will strain the episode grid and the arc columns, both drawn at seven.

Feature guide

Use your own Claude Code

Arke Studio has always come with its own engine for the writing work — the thing that actually drafts a character sheet or answers a question about your world. That engine is OpenCode, and it still ships inside the installer and is still what everyone gets.

If you already have Claude Code on your machine and you are signed in, the Studio can now use that instead. Nothing is bundled, nothing is bought, and nothing changes unless you ask for it.

The idea

Two engines, one of them yours

An engine here means the program that runs the AI work behind the scenes. You never talk to it directly. You ask the Studio for a draft; the engine is what does the drafting.

Default

OpenCode

  • Ships inside the Arke Studio installer.
  • Works on a brand-new machine with nothing else installed.
  • This is what you get if you do nothing.
  • Free and open source, so we are allowed to include it.
Optional

Claude Code

  • You install it yourself; we never ship it.
  • Uses the Claude subscription you already pay for.
  • Only used if you deliberately switch it on.
  • If it is missing or too old, the Studio just carries on with OpenCode.

Claude Code is never a fallback. The Studio will not quietly reach for it because something else went wrong, and it will not quietly stop using it either. It is used when you asked for it and it passed its checks — otherwise OpenCode does the work.

Prerequisites

What you need before it will work

RequirementWhat it meansIf it is missing
Claude Code installed The claude command, installed the normal way. The Studio looks on your system PATH, and you can point it at the file yourself if that does not find it. The Studio says Claude Code is not installed and uses OpenCode. This is a normal state, not an error.
Version 2.1.227 or newer Older builds have not been tested against the Studio's safety rules. You are told both numbers — the one you have and the one needed — so you know what to update to.
Signed in Run claude once and log in with your Claude account, exactly as you would to use it normally. The check turn fails and the Studio falls back to OpenCode rather than half-working.
A working connection Claude Code talks to Anthropic's servers, like any AI tool. The check turn cannot finish, so the engine is not offered.

A VPN can quietly break this. Some VPN setups drop slow connections after about a minute, and the Studio's longer jobs are exactly that. If the engine passes its check but real work keeps failing, try turning the VPN off before suspecting anything else.

Switching it on

How to turn it on

Settings › Harness. It lists every engine the app knows about, one per row, with its own panel — the same shape as Local runtime, so there is room for more engines and more settings without the page turning into a wall of switches.

Step one

Open Settings › Harness

Opening the page is what starts the search for Claude Code. Nothing is looked for before that, because most people will never open it.

Step two

Pick the engine

Each row says what it is: in use, available, or not here. Open a row and press Use this. There is also Check again, for when you have just installed or updated Claude Code and do not want to restart to be seen.

If it cannot find it

Point it at the file yourself

Where it is shows how the Studio found Claude Code, and offers Choose… if it did not. This matters more than it sounds: an app started from the desktop only sees the folders Windows hands it, so a perfectly good Claude Code — often under a folder like .localin — can be sitting right there and still be invisible.

A file you choose is checked exactly like one found automatically: same version floor, same test turn. Choosing one grants nothing that finding one would not have. Clear goes back to whatever the PATH offers.

Step three

Restart

The engine is chosen when the Studio starts, so the change takes effect next launch. The panel says so rather than pretending it is instant.

You cannot switch on something you do not have. If Claude Code is not on the machine, or is too old, Use this is unavailable and the row says which of the two it is — with both version numbers when that is the problem, so it is something you can act on rather than a dead end.

The refusal is not only the greyed-out button. The Studio checks again when the choice is actually made, so uninstalling Claude Code with Settings still open cannot leave you with an engine that will not start.

If you chose it and then removed it, the Studio quietly runs on OpenCode and the page says OpenCode is in use — because it is. Your choice stays saved, so reinstalling Claude Code brings it back rather than making you decide again.

There is also an ARKE_HARNESS=claude environment variable. It is a developer override for trying a build without touching real settings, and it wins where both are set.

Under the hood

What happens when you switch it on

Four steps, cheapest first. The moment one fails, the Studio stops and uses OpenCode.

Step one

Find it

The Studio looks for the claude command on your system, the same way your terminal would. It never uses a copy of its own, because the whole point is to drive the installation you already have and trust.

Step two

Check the version

Anything older than 2.1.227 is rejected without going further. This is only a quick filter to avoid wasting a real request on a build already known to be untested — it is not the actual decision.

Step three

Test it, for real

The Studio runs one small throwaway job in a temporary folder, and asks Claude Code to do something it is not allowed to do. Then it checks the folder to see whether it happened.

Why go this far? Because a version number is a claim, and this is proof. The Studio checks the result on disk rather than believing what the AI says it did — an earlier version of this check trusted the reply and reached the wrong conclusion for a week.

Step four

Remember the answer

The result is remembered per version, so the test runs once rather than every time you open the Studio. When Claude Code updates itself, the old answer no longer applies and it is tested again automatically.

Safety

What the AI is allowed to do

The same rules apply whichever engine is running. They are written down once, in plain terms, and each engine is told about them in its own language.

ActionAllowed?Notes
Read files in its working folderYesThat folder is the draft it was given, not your whole world.
Write and edit files thereYesOnly for agents whose job is drafting.
Search within that folderYesOrdinary find-in-files.
Look things up in your worldYesThrough a Studio-controlled channel, not by wandering your disk.
Run shell commandsNoBlocked. Blocking one shell is not enough, so the rule is a list of what is allowed rather than what is banned.
Reach the internet by itselfNoWeb search and page fetching are not on the allowed list.
Start its own sub-agentsNoA sub-agent escapes the rules set for the original.
Anything unrecognisedNoA real Claude Code offers about thirty tools and gains more over time. Unknown means refused.

Refused, not asked. With Claude Code the Studio never stops to ask you for permission mid-job. If the AI reaches for something outside the list, it is simply told no, and it says so and carries on. This is deliberate: a job left waiting overnight on a permission prompt nobody saw is worse than a job that was refused and said why.

Money

What it costs

Nothing extra. Claude Code signs in with your own Claude account, so the work comes out of the subscription you already pay for. There is no API key to create, paste, or keep safe, and the Studio never sees your login.

One thing worth checking. If your computer has an ANTHROPIC_API_KEY set — perhaps from other development work — Claude Code will use that instead of your subscription, and you will be billed per use for work you thought was already paid for.

Because this is silent and expensive, the Studio names the credential that answered in its startup log every time, so you can see which one is paying before the bill tells you.

Honesty

Limits worth knowing

These are all measured, not guessed. None is a reason to avoid the feature; all are things you would rather hear from us than discover.

Partial

Not every action passes the gate

Claude Code approves some harmless work by itself without asking the Studio — searching inside the folder it is already allowed to search, for instance.

What was checked: with the Studio refusing everything, nothing was written, no shell command ran, and an attempt to read a file outside the folder was caught and refused. So the boundary holds where it matters.

Untidy

Claude Code keeps its own notes

It writes a transcript of each session under your own Claude Code folder, as it does for any other work. We looked at moving this and it cannot be moved without also moving your login, which would mean holding a copy of your credentials. Not worth it.

It stays on your machine, in your own tool's folder, about your own worlds.

By design

Your own settings are ignored

The Studio deliberately does not load your personal Claude Code configuration, so your own connected tools and services are never pulled into a Studio job. Your setup is yours; Studio work runs in a clean room.

By design

The model is whatever yours is

The Studio does not pick a model for Claude Code. It uses whatever your installation is set to, so changing model is done in Claude Code, not here.

We do not ship Claude Code. The developer library we use will happily bundle a ~312 MB copy of it, and that copy is Anthropic's to distribute, not ours. The installer is built to exclude it, and the build refuses outright if it ever shows up — so the download you get contains no part of Claude Code, only the ability to use yours.

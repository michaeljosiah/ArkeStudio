# 099 — End-to-end test plan for lanes and clip sound (CDP)

Instructions for an agent driving a **local desktop build** over the Chrome DevTools Protocol.

The unit tests cover the arithmetic and the arguments. What they cannot cover is whether the
filter graph those arguments describe actually encodes.

**It does, since #428 — and finding out is what proved it previously did not.** Both lane
resolvers named a bare filename where the bytes sit under `artifacts/`, so every export carrying
a placed clip died on *No such file or directory*. The unit tests agreed with the broken path
because their fixtures supplied the very prefix the resolver forgot. With that corrected and
nothing else touched, a bed placed at 13.4s on a 67s cut encodes clean: −91 dB before the
placement, −21.1 dB across it, −91 dB after, and the film's length unchanged.

So §7 no longer asks whether the graph works. It asks the thing a hand-built plan cannot: whether
the app's own screens — a drop, a drag, a split, an export button — produce that same file. That
is still the reason this plan exists; everything before §7 is the setup that makes it reachable.

---

## 1. Use the desktop build, not the browser dev server

`npm run dev` + `npm run dev:coordinator` will render the Cut screen and let you place clips, but
**it cannot test this feature end to end**, for two reasons in `packages/coordinator/src/dev.ts`:

- It passes no `ffmpeg` runner, so every export fails with *"export needs ffmpeg — bundled in
  packaged builds"*. `ARKE_FFMPEG` is read by `apps/desktop/src/main.ts`, **not** by `dev.ts`.
- It passes no `mediaProbe`, so nothing is ever measured. Splitting refuses any video whose
  `mediaInfo` is absent, so **split is unreachable in dev** unless you pre-seed the measurement
  (§3.3 does exactly that, and is worth doing in either environment).

Use the browser dev server only for fast selector work. Every assertion below assumes the desktop
build.

## 2. Prerequisites

| Need | Check |
|---|---|
| Node ≥ 20 | `node -v` |
| Repo deps | `npm install` at the repo root |
| An ffmpeg that has the filters **and runs them** | see §2.1 — this is the one that bites |
| Chromium/Electron able to open a window | a display, or `xvfb-run` |

### 2.1 ffmpeg — the bundled pair, not PATH

A packaged build runs `resources/ffmpeg/ffmpeg.exe` (`apps/desktop/src/main.ts`), so a check
against whatever the machine has on PATH is checking a binary the app never invokes. The same
pair is staged in the checkout at `apps/desktop/build-resources/ffmpeg/` — but that directory is
**gitignored**, so a fresh clone and every worktree lack it until you stage it:

```bash
npm run prepare:runtimes:x64 --workspace @arke-studio/desktop   # Windows only
export ARKE_FFMPEG="$PWD/apps/desktop/build-resources/ffmpeg/ffmpeg.exe"
export ARKE_FFPROBE="$PWD/apps/desktop/build-resources/ffmpeg/ffprobe.exe"
```

Anywhere else, point `ARKE_FFMPEG` at a full build of your own — and then check it twice, because
there are two separate ways for one to be unusable.

**Does it have the filters?** The graph needs `amix`, `adelay`, `apad`, `atrim`, `concat`,
`overlay` and `drawtext`. Many stripped builds have almost none of them — Playwright's bundled
`ffmpeg-linux`, for instance, is built `--disable-everything` and has only `atrim` of that list.

```bash
FF=${ARKE_FFMPEG:-ffmpeg}
for f in amix adelay apad atrim concat overlay drawtext; do
  printf '%-9s ' "$f"
  "$FF" -hide_banner -filters 2>/dev/null | grep -qE "^ [TSC.]* $f " && echo present || echo MISSING
done
```

**Does it run them?** A listed filter is a table the build was compiled with, not evidence that
anything works. `drawtext` is the one to actually run: it reaches outside ffmpeg for a font, so a
build whose fontconfig has no config file **segfaults** on it rather than falling back — and
every gap in a cut draws a slate, so that kills the export rather than the slate. Windows' winget
ffmpeg (gyan.dev 8.1.1-full) does exactly this. The bundled 8.1.2 prints the same fontconfig
error and draws anyway, which is the whole argument for using it.

```bash
"$FF" -hide_banner -loglevel error -f lavfi -t 0.1 -i color=c=black:s=64x64:r=24 \
  -vf drawtext=text=probe:fontcolor=white:fontsize=12 -f null - && echo runs || echo BROKEN
```

Any `MISSING`, or `BROKEN`, means §7 cannot run. Say so in your report rather than reporting a
passing export. Skip this and run against a segfaulting build and every export with a gap fails
in a way that reads exactly like a lanes bug — which is the wrong thing to spend a session on.

`scripts/e2e-lanes.mjs` performs both checks in its own preflight and blocks on either.

## 3. Build a disposable app root

Never test against `~/ArkeStudio`. `ARKE_STUDIO_ROOT` overrides it
(`packages/coordinator/src/world/paths.ts`).

### 3.1 Seed from the fixture world

```bash
export ARKE_TEST_ROOT=/tmp/arke-lanes-test
rm -rf "$ARKE_TEST_ROOT"
mkdir -p "$ARKE_TEST_ROOT/worlds"
cp -r fixtures/worlds/the-undersong "$ARKE_TEST_ROOT/worlds/the-undersong"
```

This gives you world `the-undersong` (id `01J8F3K2QW9VZX4N7M0RTYB6HC`) with production
`saltlight`, whose derived cut is about **10 seconds** — non-zero, which matters because lanes
refuse drops when `totalSec <= 0`.

### 3.2 The fixture files no video

Its three artifacts are a board (`board-v2.png`), an audio bed (`harbour-bells.wav`) and a
document (`undersong-treatment.pdf`). **Splitting needs a video**, so seed one.

### 3.3 Seed a video artifact with its measurement

The in-app *Upload* button opens a native OS picker, which CDP cannot drive. Seed on disk
instead. Do this **before launching**, because the scan happens when the world opens.

```bash
W="$ARKE_TEST_ROOT/worlds/the-undersong/artifacts"
# Any bytes will do for placement and split; §7 replaces this with a real encode.
printf 'placeholder' > "$W/insert.mp4"
cat > "$W/insert.mp4.json" <<'JSON'
{
  "id": "ar_01J8G0000000000000000000V1",
  "kind": "video",
  "file": "insert.mp4",
  "hash": "sha256:deadbeefdeadbeef",
  "origin": { "by": "user" },
  "links": [],
  "mediaInfo": { "durationSec": 12, "hasAudio": true },
  "created": "2026-08-01T10:00:00Z"
}
JSON
```

Three things about that sidecar, each of which silently drops the artifact if you get it wrong —
`tryParse` skips anything that fails the schema, with no log line:

- **`links` is required.** Omitting it is the easy mistake; the artifact simply never appears.
- **`kind` must be `video`.** Split refuses every other kind.
- **`mediaInfo.hasAudio: true` is what makes split available at all.** Without it the clip is
  "not measured yet" and split refuses — correctly. Seed it here, and additionally test the
  unmeasured path in **T9** by seeding a second artifact with `mediaInfo` omitted.

Also seed a **silent** video for **T8**, identical but with a different `id`/`file` and
`"mediaInfo": { "durationSec": 12, "hasAudio": false }`.

Confirm all of it landed before going further — if an artifact is missing here, every later
failure will be misattributed:

```bash
ls "$ARKE_TEST_ROOT/worlds/the-undersong/artifacts/"
```

## 4. Launch with CDP

```bash
# Builds the client too, then bundles the main process into apps/desktop/dist/main.cjs.
npm run build --workspace @arke-studio/desktop

# ARKE_FFMPEG/ARKE_FFPROBE as exported in §2.1 — never `$(command -v ffmpeg)`, which is how a

npx electron apps/desktop/dist/main.cjs --remote-debugging-port=9222
```

Headless hosts: prefix with `xvfb-run -a`.

Attach with `playwright-core` (Chromium is at `/opt/pw-browsers/chromium` where preinstalled):

```js
import { chromium } from 'playwright-core';
const browser = await chromium.connectOverCDP('http://127.0.0.1:9222');
const page = browser.contexts()[0].pages()[0];
```

Raw CDP works equally well; everything below is plain DOM and translates to
`Runtime.evaluate` / `Input.dispatchMouseEvent` directly.

## 5. Navigate

The client uses **HashRouter**, so set the hash — do not construct a path URL:

```js
await page.evaluate(() => {
  location.hash = '#/w/01J8F3K2QW9VZX4N7M0RTYB6HC/p/saltlight/cut';
});
await page.waitForSelector('[data-screen="cut"]');
```

There is no first-run gate once the root has a world: the shell only routes to `/first-run` when
`worlds.length === 0`.

## 6. Selectors and the two gestures

### 6.1 Selectors

| What | Selector |
|---|---|
| The screen | `[data-screen="cut"]` |
| Artifact panel rows (drag sources) | `.fy-artrow[draggable="true"]` |
| A lane's drop target | `.fy-ovlane` (one per lane, top row = highest lane) |
| Lane labels | `.fy-track__label` → `L0`, `L1`, … |
| A placed clip | `.fy-ovclip` |
| Sound-only clip | `.fy-ovclip--sound`, badge `.fy-ovclip__badge` reads `A`; muted reads `MUTE` |
| Trim handles | `.fy-ovclip__grip--start`, `.fy-ovclip__grip--end` |
| Remove (×) | `.fy-ovclip__x` |
| Context menu | `.fy-clipmenu`, items `.fy-clipmenu__item`, refusal reason `.fy-clipmenu__note` |
| Add lane | button in `.fy-clanes__foot` |
| Preview / transport | `.fy-cutviewer`, `.fy-playbtn`, scrubber `.fy-scrub` |
| Header summary | `.fy-h1row__meta` (reads `· N clip`/`clips`) |

**Lanes are drawn highest-first**, so `.fy-ovlane` index `0` in DOM order is the *highest* lane
and the last is `L0`. A higher lane composites nearer the viewer, and "split to the lane below"
means one row down the screen.

### 6.2 Dropping an artifact — synthetic `DataTransfer`

CDP's Input domain **cannot** perform HTML5 drag-and-drop. Dispatch the events with a constructed
`DataTransfer`. *(This snippet was verified against Chromium — the handler receives both the id
and the correct `clientX`.)*

```js
async function dropArtifact(page, artifactRowIndex, laneIndexFromTop, fraction) {
  await page.evaluate(({ artifactRowIndex, laneIndexFromTop, fraction }) => {
    const src = document.querySelectorAll('.fy-artrow[draggable="true"]')[artifactRowIndex];
    const lane = document.querySelectorAll('.fy-ovlane')[laneIndexFromTop];
    const dt = new DataTransfer();
    src.dispatchEvent(new DragEvent('dragstart', { bubbles: true, cancelable: true, dataTransfer: dt }));
    const box = lane.getBoundingClientRect();
    const opts = {
      bubbles: true, cancelable: true, dataTransfer: dt,
      clientX: box.left + box.width * fraction,
      clientY: box.top + box.height / 2,
    };
    lane.dispatchEvent(new DragEvent('dragover', opts));
    lane.dispatchEvent(new DragEvent('drop', opts));
  }, { artifactRowIndex, laneIndexFromTop, fraction });
}
```

The lane derives the drop time from `clientX` against its own box, so `fraction` is the position
in the film: `0.25` on a 10s cut places the clip at 2.5s.

### 6.3 Moving and trimming — real mouse events

These are pointer gestures with `setPointerCapture`, and the Input domain drives them correctly.
*(Also verified: an 80px drag across a 400px lane on a 20s film yields 4.0s, and −50px vertically
yields one lane up.)* Use real mouse input, **not** synthetic `PointerEvent`s:

```js
const box = await page.locator('.fy-ovclip').first().boundingBox();
await page.mouse.move(box.x + box.width / 2, box.y + box.height / 2);
await page.mouse.down();
await page.mouse.move(box.x + box.width / 2 + 120, box.y + box.height / 2, { steps: 10 });
await page.mouse.up();     // the write happens once, on release
```

Grab `.fy-ovclip__grip--start` / `--end` the same way to trim. One lane is **50px** of vertical
travel. Nothing is written until `mouseup`, so assert on disk only after release.

### 6.4 Reading the truth

The UI is a projection. The authority is on disk:

```bash
cat "$ARKE_TEST_ROOT/worlds/the-undersong/productions/saltlight/cut.json"
```

Every clip is `{ id, artifactId, startSec, endSec, lane, audio }` where `audio` is
`keep` | `mute` | `only`. Assert against this file, not only against the DOM.

## 7. Test cases

Reset between cases by deleting `cut.json` and reloading, or rebuild the root from §3.

### T1 — Lanes rest at two, and both accept a drop
Open the Cut. Expect exactly two `.fy-ovlane`, labelled `L1` then `L0`. Drop the audio bed onto
`L0` at `fraction 0.2`. Expect one `.fy-ovclip`, and `cut.json` holding one clip with `lane: 0`,
`audio: "keep"`, `startSec ≈ 2.0`, `endSec ≈ 6.0` (the 4s default, clamped by the film).

### T2 — A lane has no type
Drop the **board** image onto `L1` and the **audio bed** onto `L0`. Both must place. This is the
core claim: no lane rejects a kind. Header reads `· 2 clips` (plural).

### T3 — Add lane
Press *Add lane*. Expect three `.fy-ovlane` (`L2`, `L1`, `L0`). Drop onto `L2`; expect
`lane: 2` on disk. Keep pressing: the cap is **16 lanes** (`L15`…`L0`, since `MAX_CLIP_LANE` is
15), at which point the button is disabled.

### T4 — Move along the ruler
Place a clip, then drag its body right by a quarter of the lane width. Expect `startSec` on disk
to increase by ~¼ of the cut, the duration to be **unchanged**, and `lane` unchanged. Drag far
past the end and expect the clip to stop with its tail on the end, not squashed.

### T5 — Move across lanes
Drag a clip on `L0` upward by 50px. **During** the drag the clip must visibly move rows (a
`translateY` is applied); on release, `lane` on disk becomes `1`. A clip that only slides
horizontally during the drag is a regression of the lane-feedback fix.

### T6 — Trim
Drag `.fy-ovclip__grip--end` right. Expect `endSec` to grow and `startSec` to be untouched; then
the start grip, and the reverse. Drag either edge through the other and expect the clip to stop
at 0.1s long — never inverted.

### T7 — Split, and rejoin
Drop `insert.mp4` (the measured-with-audio video) onto `L1`. Right-click it → the menu offers
*Split audio to the lane below*. Take it. Expect on disk:

- the original now `audio: "mute"`, `lane` unchanged, window unchanged
- a **second** clip, same `artifactId`, same window, `lane: 0`, `audio: "only"`
- in the DOM, the sound half carries `.fy-ovclip--sound` and badge `A`; the picture reads `MUTE`
- the header still reads `· 1 clip` — a split is not a second placement

Right-click the muted picture → *Rejoin its sound*. Expect one clip again, `audio: "keep"`, and
the sound half gone.

Then repeat the split, **drag the sound half elsewhere**, and rejoin: the moved clip must
**survive** (it is an edit now, matched by window, not swept up).

### T8 — Split refuses a silent video
Right-click the seeded silent video. The split item must be **disabled**, with
`.fy-clipmenu__note` reading *measured as silent*. Confirm `cut.json` is unchanged — a refusal
that mutes the picture anyway is the exact bug this guard exists for.

### T9 — Split refuses an unmeasured video
Same, with the artifact whose sidecar omits `mediaInfo`. Note must read *not measured yet*. The
two silences must read differently; identical wording is a regression.

### T10 — Menu dismissal
Right-click a clip, then: press Escape (closes); reopen, click outside the lanes entirely
(closes); reopen, scroll (closes). Right-click a clip near the right edge and confirm the menu
stays fully inside the viewport.

### T11 — Preview still plays
Press *Watch from top*. The `<video>` inside `.fy-cutviewer` must advance and the playhead move.
**Known gap, not a failure:** overlays are not composited into the preview — you will not see
placed clips there. Only the export shows them.

### T12 — Export with no placed sound is unchanged
With an empty `cut.json`, export a *Review cut*. It must succeed. Keep this file; it is the
baseline for T13.

### T13 — Export carries the sound *(the point of this plan)*
Place the audio bed at 2s on `L0` and export again. Then verify **the file, not the UI**:

```bash
OUT="$ARKE_TEST_ROOT/worlds/the-undersong/exports"
ffprobe -v error -show_streams "$OUT/<newest>.mp4" | grep codec_type
```

Assert, in order of what actually proves the feature:

1. An **audio stream exists** (T12's baseline has none).
2. It is **silent before 2s and audible after** — decode to wav and inspect, e.g.
   `ffmpeg -i out.mp4 -f wav - | ...`, or `ffmpeg -i out.mp4 -af astats -f null -` over trimmed
   ranges. A file that has an audio track of pure silence is a **failure**, and is exactly what a
   wrong `adelay`/`atrim` chain produces.
3. Placing a **second** sound overlapping the first must not make the first quieter. This is the
   `normalize=0` claim; a duck of roughly 6 dB means it regressed.
4. The film's **duration is unchanged** by a sound placed near the end.

If any of these fail, capture the exact ffmpeg argv. The coordinator builds it in
`buildFfmpegArgs` (`packages/contracts/src/cut.ts`); log it or reconstruct it from the plan.

### T14 — Placed picture reaches the export
Place the board image at 1s–5s and export. Confirm the frame at 3s shows it and the frame at 7s
does not:

```bash
ffmpeg -ss 3 -i out.mp4 -frames:v 1 f3.png
ffmpeg -ss 7 -i out.mp4 -frames:v 1 f7.png
```

### T15 — Known limits, confirm rather than file
Two behaviours are **expected** and should be reported as confirmations, not bugs:

- **Episode and spine exports discard placed clips.** On an episodic or spine production the
  lanes accept drops and the export silently omits them. Confirm it still does; do not "fix" it.
- **Trim, move and split are pointer-only.** No keyboard path exists.

## 8. Teardown and reporting

```bash
rm -rf "$ARKE_TEST_ROOT"
```

Report, per case: pass / fail / blocked, and for every failure the **`cut.json` before and
after** plus the ffmpeg argv where an export is involved. Two distinctions matter more than the
pass count:

- **A refusal that still mutated `cut.json` is worse than a crash** — it is silent data loss from
  an action that reported itself as refused. Call these out first.
- **"The export succeeded" is not a result.** T13 fails if the audio track exists but is silent,
  which is exactly what a wrong `adelay`/`atrim` chain produces. The graph itself has been
  measured by hand since (see the opening), so a silent track here more likely means the app fed
  it something other than what that measurement fed it — which is the thing this plan is for.
  Report what you measured in the file, not that the encode exited zero.

If §2.1 showed missing filters or a `drawtext` that will not run, or no display was available,
report those cases as **blocked** — never as passing.

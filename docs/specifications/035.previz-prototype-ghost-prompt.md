# 1 · Requirements

## 1.1 Summary

A dedicated prototype page proves a proxy 3D previz can show shot
framing and animated shot progression, and that an agent editing the
shot plan produces the same prompt the video generator will receive —
before any core integration. The prototype is an isolated route that
derives everything it shows from existing `Scene`/`Shot` and
`planning.ts`/`pass-compiler.ts` authorities; it writes no new world
state beyond what `Scene` already stores.

Tracking: this spec gates core integration — core Storyboard/Flow
previz work does not start until the prototype's success criteria
(§1.6) pass.

## 1.2 Bound decisions

1. **Proxy geometry is derived, not stored.** Capsules/boxes for
   characters + a location plane — no mesh import, no rig.
2. **Viewport is observer, not editor (prototype).** Framing edits
   remain in `Shot.framing` via `ShotSheetScreen` / agent proposal;
   the viewport renders the derivation.
3. **Ghost is proposal overlay, not a second authority.** Ghost
   renders `.proposals/<id>/` staged scene beside the accepted scene.
4. **Prompt is composed, never duplicated.** Prototype calls
   `promptFor`/`planForScene`/`compilePasses` — the same functions
   dispatch uses. No new prompt assembler.
5. **Agent path reuses `scene-writer`.** No new agent; skill doc is
   updated with framing vocabulary.

## 1.3 Scope

**In scope (prototype):**

- Dedicated route `/w/:worldId/p/:prodId/previz/:sceneId`.
- ThreeJS vanilla + `OrbitControls` + `three-viewport-gizmo`
  (dedicated small canvas for WebGPU safety) + infinite grid shader.
- `framingToPose()` pure mapping `ShotFraming` → camera pose and
  `proxy-scene.ts` derivation from `WorldBundle` + `Scene`.
- Modes: Explore (free orbit), Frame (lock to shot N), Play (animatic
  via `useTransport` + `useScrubDrag`, solid and ghost timelines).
- Ghost toggle: Solid / Ghost / Diff (ghost = staged proposal scene
  when one targets this scene); prompt pane Solid vs Ghost with
  `bindingPreamble`/`derivedNegatives`/estimate diff.
- Failure/empty handling and narrow/collapse contract.

**Out of scope (prototype):**

- In-viewport framing edit, `TransformControls` placement, ortho,
  post-processing/DOF, mesh/asset import, board screenshot export,
  multi-scene cut playback. Each is a named follow-up.

## 1.4 Acceptance criteria

### Prototype isolation

- [ ] New route is additive; no modification to `storyboard.tsx`,
  `production.tsx`, `planning.ts`, `pass-compiler.ts` beyond a route
  entry and a read-only staged-scene selector (**R-1**).
- [ ] `three` is lazy-imported on the previz route only; other routes
  pay no bundle cost (**R-2**).

### Proxy scene and framing

- [ ] Proxy scene derives from `scene.inherits.location` + `@mentions`
  resolved via `parseMentions`/`resolveCast`; no stored geometry
  (**R-3**).
- [ ] `framingToPose(effectiveFraming(scene, shot))` maps every
  `ShotFraming` field (`scene.ts:51-65`) to a concrete
  `{position, quaternion, fov, target}`; `lens` ↔ `fov`, `movement`
  ↔ motion curve as specified in §2.5 (**R-4**).
- [ ] Frame mode locks camera to selected shot's pose; Explore uses
  `OrbitControls`; controls do not fight animation (stop calling
  `update()` during Play) (**R-5**).

### Ghost preview

- [ ] When a proposal targeting the viewed scene is open, ghost
  frustums/capsules/timeline render at reduced opacity beside solid;
  Diff inspector lists changed shots/fields (**R-6**).
- [ ] Ghost reads staged `Scene` from `world.proposals` snapshot
  (or one new read-only `get_proposal_scene` tool if not yet
  surfaced); agent writes remain proposal-scoped per
  `confinement.ts:154-169` (**R-7**).
- [ ] No ghost when no proposal; no proposal mutation from viewport
  (**R-8**).

### Animation

- [ ] Play scrubs via `useTransport` (`playback-engine.ts:56-110`)
  reusing `timeRef`; manual `lerp`/`slerp` (quaternion, never Euler)
  + `CatmullRomCurve3.getPointAt` for tracking; `camera.updateProjectionMatrix`
  after `fov` writes (**R-9**).
- [ ] Timeline uses `useScrubDrag` (`timeline-drag.ts:102-156`) with
  snap to shot boundaries; Play/Pause respects `durationSec`
  (default `DEFAULT_SHOT_SEC`) and `spanAt`-style lookup
  (`cut-playback.ts:64-71` shape) (**R-10**).

### Prompt accuracy

- [ ] Prompt pane calls `promptFor` per shot and
  `planForScene` → `compilePasses` for whole-scene, showing Solid
  and Ghost `params.prompt`, preamble, negatives, estimate and
  warnings verbatim — equal to what coordinator will enqueue
  (**R-11**).
- [ ] Agent draft via existing `scene-writer` skill (updated with
  `CAMERA_FIELDS` vocabulary) produces visible ghost + prompt delta
  without dispatching (**R-12**).

## 1.5 Open questions

- Whether ghost defaults to overlay or split-view (overlay first,
  split as fallback).
- Exact `ShotFraming` → pose numerics (provisional, tunable).

## 1.6 Success gate (prototype → core integration)

All of: ghost visibly diverges on proposal framing change; both
timelines scrub at 60fps without reconciler jank; ghost prompt
equals `compilePasses` output verbatim; agent draft yields ghost;
typecheck/build/test green; no core-screen regression.

# 2 · Design

## 2.1 Architectural decision

**One derivation, two renderings.** `Scene` is the sole authority.
`framingToPose` + `proxy-scene` + `assemblePrompt` are pure
projections; ghost is the same projection over the staged authority.
The video prompt is `compilePasses` over the same shot plan — so
framing, previz, and prompt cannot disagree.

Rejected: viewport-owned camera state, duplicated prompt builder,
agent direct scene-graph mutation.

## 2.2 Source-of-truth map

| Fact | Authority | Viewport treatment |
| --- | --- | --- |
| Shot framing | `Shot.framing` + `Scene.defaults` via `effectiveFraming` | `framingToPose` → pose |
| Shot order | `SceneSequence` / `linearizeSceneFlow` | `spanAt`-style active shot |
| Cast | `@mentions` → `resolveCast` | Proxy capsules filtered by cast |
| Prompt | `planning.ts:assemblePrompt`/`promptFor`/`compilePasses` | Preview pane, Solid vs Ghost |
| Ghost | `.proposals/<id>/` staged `Scene` | Overlay, read-only |
| Camera pose | Derived from framing, never stored | Ephemeral, not versioned |

## 2.3 Data flow

Live Scene → effectiveFraming → framingToPose → solid poses →
assemblePrompt/planForScene/compilePasses → solid prompt/estimate;
Staged Scene → same chain → ghost poses/prompt/delta; Viewport
renders both; Play interpolates via shared `useTransport` clock.

## 2.4 Persisted example (no new file)

Uses existing `productions/<p>/scenes/<slug>.json` `Shot.framing`
fields; prototype adds no persisted key.

## 2.5 Motion mapping

`Static`=hold; `Slow push-in`/`Pull back`=dolly ±Z + fov lerp;
`Pan`/`Tilt`=yaw/pitch slerp; `Tracking`/`Dolly, follow`=
dual `CatmullRomCurve3`; `Orbit`/`Crane`=arc via `Spherical`;
`Handheld`=low noise atop base.

## 2.6 UI contract

Dedicated route with 3D viewport (full), inspector rail (shot list,
ghost toggle, effective framing, Solid vs Ghost prompt + estimate
+ warnings diff), top bar scene selector + agent entry. Collapses:
inspector folds, timeline wraps. No core Storyboard/Flow change.

## 2.7 Failure vocabulary

No scene → empty state; invalid scene → message + history; no
proposal → ghost toggle disabled; WebGL unavailable → message.

## 2.8 What this does not do

No in-viewport framing write, no placement via `TransformControls`,
no ortho, no post-processing, no mesh import, no screenshot artifact,
no cross-scene cut. Each is a separate spec.

|---|---:|---|

| D6 | Dedicated route | Isolation gate before core change |

| D8 | Lazy three import | Bundle isolation |

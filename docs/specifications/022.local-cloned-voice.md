# 1 · Requirements

## 1.1 Summary

A character can be given a voice that exists nowhere but this machine: a clip somebody recorded,
turned into a voice the picker offers and the bench reads. The engine is IndexTTS 2.5 running as a
**ComfyUI recipe** — unmetered like Kokoro, gated on VRAM like an Ollama row, and dispatched through
the provider client SPEC-021 already ships.

Two things arrive together because neither works alone. IndexTTS **ships with no voices at all** —
its voice is a wav file, not a catalogue entry — so the engine is unreachable until the clone path
exists. And SPEC-011 §2.7 designed that clone path (*"the recording is filed as an artifact linked
to the sheet"*) and never built it: today `canClone` is a flag nothing acts on. This spec builds
the library and the engine that needs it.

It also retires a rule. SPEC-011 §2.3 says **local means presets, cloud means cloning**. IndexTTS
is local and clones. The rule was a true description of Kokoro, not a principle, and §2.4 below
replaces it.

## 1.2 Scope

**In scope**

- A shipped `voice-tts` **recipe** in the SPEC-021 catalogue, dispatched through `ComfyUiClient`
  unmodified — no new provider, no second path around the queue.
- Widening `ComfyUiRecipe.capability` and the `comfyui` provider row to admit `voice-tts`.
- A **world-level cloned-voice library**: a clip becomes a catalogue entry with a minted id, a
  name, and a description that is extracted into matchable attributes.
- The picker's third catalogue state — a source that is working correctly and lists nothing.
- Clone capture: record or import, consent, file the recording as an artifact for provenance.
- Per-model hardware gating over the probe already in the tree (`probeRuntime` → `gateLocalRuntimes`).
- Removing the two-provider assumption from the voice service (§2.7).

**Out of scope (this spec)**

- **Emotion reference clips.** Delivery maps to the model's 8-float emotion vector (§2.5); a
  second clip per voice is a larger surface for no gain the six deliveries need.
- **Cloud cloning.** ElevenLabs' clone route stays unbuilt. `canClone` on a cloud row remains a
  flag nothing acts on, and this spec does not widen it.
- **Shipping weights in the installer.** ~10.2 GB, fetched on demand like a SPEC-021 recipe's.
- **Streaming and realtime.** Poll-based, like every other client.
- **`use_accel`.** It requires `flash-attn`, which publishes no Windows wheel; requiring every
  user to build it from source is not a configuration this app can ship (§2.6, D4).

## 1.3 Acceptance criteria

### The engine

- The recipe states its readiness with a measured reason, in the vocabulary SPEC-021 §2.2
  established. A machine below the floor reads `Needs 6 GB VRAM. This machine has 4 GB.` and names
  the cloud alternative; an unmeasurable floor reads that it could not be measured and **still
  dispatches** (SPEC-008 D12).
- A machine with no ComfyUI reads as *local cloned voice needs ComfyUI*, with the remedy — never as
  a failed take (R-4). Kokoro and cloud voices are unaffected and keep working.
- The recipe's pinned custom node and checkpoints are verified before dispatch (SPEC-021 R-9); a
  drifted node refuses rather than runs.

### The library

- A cloned voice belongs to the **world**, not to the sheet it was made for, and is offered for
  every character afterwards.
- A cloned voice requires a name and a description. The description is lexically extracted into
  `attributes` by the existing `extractVoiceAttributes`, so `rankVoices` can rank it.
- The recording files as an artifact recording where it came from. Deleting that artifact does
  not silently break the voice: the voice reports itself unusable with the reason.
- Consent is recorded once, at capture, as a required tick.

### Generation

- A voice line dispatched to the recipe is a job like any other — numbered, priced at nothing,
  re-runnable, recoverable after a crash.
- A take carries the voice that made it (SPEC-011 turn 70), so a character can afterwards be
  given the voice from a recording.
- Delivery maps to the emotion vector; a delivery the engine cannot express is stated, never
  silently dropped (SPEC-011 R-15).

### The picker

- The cloned-voice source renders its empty state with a count (`no voices`) and a disabled
  assign, with no illustration and no explanatory sentence (turn 69's binding).
- A local voice shows no price where a cloud voice shows an exact per-character figure (turn 70).

## 1.4 Open questions

- **D1 · Whether the engine ships managed at all. CLOSED 2026-08-19: we ship no engine.** ComfyUI is
  the runtime, and it is already a prerequisite for local image and video (§2.1). Nothing Python
  enters this repository and no CUDA matrix becomes ours. If ComfyUI's own install friction later
  proves too high, the escape hatch is a user-directed path setting mirroring `comfyUiModelsDir` —
  "point Arke at a Python that can run this" — which serves the few who genuinely have such an
  environment without committing us to supporting the general case. That is an expert's hatch, not
  a distribution strategy, and it is deliberately not built now.
- **Whether `torch.compile` is on by default.** It is worth ~16% (§2.6) and costs ~41 s at every
  launch, breaking even near five minutes of generated audio. A per-session choice is possible;
  a default is simpler and this spec proposes one.
- Whether a cloned voice can be exported, or shared between worlds. Out of scope, but the id
  minting in §2.3 should not foreclose it.

# 2 · Design

## 2.1 Architectural decision

**A ComfyUI recipe, not a runtime of our own.**

Running any model of this class means running a Python program. The weights are inert without it:
tokenising the text, the autoregressive loop, the decoder, the vocoder and — for IndexTTS — five
languages of text normalisation, all of it PyTorch. Kokoro is the exception this app already relies
on, and only because it is small enough (82M, no cloning, no generation loop) that an ONNX export
fits inside Voxa's .NET binary. A 0.8B cloning model is not that.

So the choice was never Python or TypeScript. It was **own that environment, or borrow one**:

- **Own it** — package a Python runtime with CUDA wheels, per architecture, and inherit the driver
  and version matrix on every user's machine. SPEC-021 D1 weighed this exact cost for ComfyUI and
  deferred it; taking it on for voice would answer that question by accident.
- **Borrow it** — ComfyUI *is* a managed Python environment for models, and is already the
  prerequisite for local image and video. Voice rides along at near-zero marginal friction, and no
  Python enters this repository.
- **Wait for a binary** — llama.cpp ported Qwen3-TTS to C++, which is the shape Kokoro has. Measured
  at RTF ~26 on the target GPU with every layer on CUDA0 (§2.10), so not yet.

Borrowing wins, and it wins twice: discovery, weight fetching, VRAM gating, supervision and
pinned-dependency verification all already exist (SPEC-021) rather than needing to be built here.

The decisive property is that **the engine becomes swappable**. A voice is addressed as
`{provider, voiceId}` with the recipe as the model behind it, so replacing IndexTTS with VoxCPM2 —
or with a llama.cpp binary when one is fast enough — is a recipe edit, not a rewrite. In a field
where the model under evaluation was eight days old and its llama.cpp support two weeks old, that
optionality is worth more than picking correctly today.

**The cost, stated plainly.** Local cloned voice requires ComfyUI. For someone already running it
for local image and video that is free; for someone who wants only a free voice it is a 10 GB
install they did not otherwise need. The bet is that offline-voice users are offline-everything
users. That is an assumption, recorded here so it is visible if it proves wrong.

## 2.2 What the recipe is

A shipped, versioned recipe like any other (SPEC-021 R-2), declaring `capability: "voice-tts"`,
its graph template, the pinned custom node that carries the engine, the checkpoints it needs, and
its VRAM floor.

The graph takes the reference clip and the line, and its output node saves a wav. Nothing else in
the app changes shape: the recipe projects into the manifest (SPEC-021 R-3), so the picker's
copy, the estimate — zero, unmetered — and pass packing need no special case, and
`ComfyUiClient.fetchArtifacts` already walks the declared output node for anything carrying a
filename, which is exactly the shape ComfyUI's audio save nodes emit.

**The node is a supply-chain dependency and should be read as one.** The engine reaches us through
a community custom node rather than the vendor's own inference. One candidate wrapper was already
abandoned — untouched since October 2025 — while `diodiogod/TTS-Audio-Suite` added IndexTTS 2.5
support two days after the model released and ships actively. SPEC-021 R-9's pinned-digest
verification is what makes that dependency safe to hold: a node that drifts from what the recipe
was authored against refuses rather than runs.

## 2.3 A voice is a clip, and the library is what makes it a voice

Everything in the app addresses a voice as `{provider, voiceId}` — `VoiceAssignmentSchema` on the
sheet, `VoiceCandidate` in the picker, `params.voiceId` on the wire. IndexTTS has no voice ids.
The library is the adapter: a clip in, a minted id out, and from then on the voice is addressed
like every other.

Stored per voice: the id, the name, the description and its extracted attributes, the artifact id
of the recording, and the path dispatch resolves to `spk_audio_prompt`.

**World-level, not sheet-level.** SPEC-011 §2.7 files the recording against the sheet, and that
stays — as *provenance*, answering where a voice came from months later. Ownership is different:
`catalogue()` is assembled independently of any sheet and only then ranked against one, so a
sheet-owned voice has nowhere to live in the shape the picker already has, and one actor's clip
could not voice two roles.

**The description is required** because it is data, not decoration. A cloned clip arrives with no
provider metadata, and `rankVoices` ranks a candidate with no attributes last — so a voice cloned
*for* a character would sink below every preset when ranked against that same character.

## 2.4 Local no longer means presets

SPEC-011 §2.3's line — *local means presets, cloud means cloning* — described a catalogue with one
local engine in it. With two, the honest split is per engine, stated on the thing refused:

- Kokoro: six presets, instant, cannot clone. The clone row in its pane reads `Kokoro · presets only`.
- IndexTTS: clones from a clip, roughly realtime, empty until you make one.

This is the same posture as `deliveryParams` refusing a delivery Kokoro cannot express: a clause
on the control, not a paragraph above the grid.

## 2.5 Delivery is the emotion vector

The model takes eight floats — `[happy, angry, sad, afraid, disgusted, melancholic, surprised,
calm]` — plus `emo_alpha` and `duration_factor`. That covers all six deliveries honestly, where
Kokoro shapes pace only and openly refuses four of them. Measured: identical text at `sad` and
`calm` produced 9.41 s and 6.45 s of audio, so the control does something audible rather than
nominal.

The clip is **not** a reference in the SPEC-019 sense. Turn 74 records this as binding: a cloned
voice's recording is the voice's identity, chosen once when the voice is made, so it is never
budgeted, never counted against `referenceImages`, and never appears on the bench. Voice mode
still offers no reference lanes (SPEC-011 turn 70).

## 2.6 What was measured, and what it constrains

Benchmarked 2026-08-18 on an RTX 3080 (10 GB, driver 591.86), bf16, against the repository's own
English reference clip.

| | |
|---|---|
| Steady RTF, `use_torch_compile` | **1.11 – 1.15** |
| Steady RTF, uncompiled | 1.28 |
| Model load | 39 s |
| First synthesis (compile) | 41 s |
| Time to first line | **80.5 s** |
| Peak VRAM | 5.44 GB |
| Weights on disk | 5.1 GB + 5.1 GB auto-fetched auxiliaries |

Four constraints follow. Two are now the recipe's rather than ours — ComfyUI owns how the model is
invoked — but they are recorded because a recipe author has to honour them, and because the numbers
above were measured with them set this way:

1. **`use_cuda_kernel` must be pinned `False`** (recipe-level). It does not degrade gracefully: with no `nvcc` on
   the machine the fused BigVGAN kernel fails to build and falls back to a path measured at
   **RTF 2.60 — twice as slow as leaving the flag off**.
2. **`use_accel` is unshippable** and must not be offered (recipe-level). It hard-requires `flash_attn`
   (`model_v2_5.py` raises `ImportError` without it), which has no Windows wheel.
3. **`torch.compile`'s cost does not amortise across restarts.** A second process start paid the
   same ~41 s; the inductor cache did not help. Compile is once-per-launch, and the break-even
   against the uncompiled path is ~5 minutes of generated audio.
4. **Speaker conditioning is a single-slot cache** — ours, because job ORDER is ours (§2.8) keyed on the clip path (`infer_v2_5.py`:
   `if self.cache_spk_cond is None or self.cache_spk_audio_prompt != spk_audio_prompt`). Switching
   voices discards it, so a scene generated in script order re-encodes the reference on every
   speaker change. Voice jobs for a scene are therefore **ordered by voice, not by line** (§2.8).

The floor is stated as **6 GB VRAM**, above the 5.44 GB measured peak, and gated through
`gateLocalRuntimes` with no new detection written.

## 2.7 The two-provider assumption has to go first

The voice service assumes local ≡ Kokoro and cloud ≡ ElevenLabs. Three places break on a third
provider, and all three are pre-existing defects rather than new work:

- `previewCacheFile` classifies with `provider === "kokoro" ? "kokoro" : "elevenlabs"` and the same
  for the model id, so a second local provider is filed under ElevenLabs — wrong cache key.
- `candidates()` finds the voice model with `m.provider === "elevenlabs" && m.capability === "voice-tts"`,
  so a third row is simply not found.
- `cloudPreviewRequest` takes `provider` as a parameter and then hardcodes `"elevenlabs"` in the
  cache key, so two providers' previews of the same voice id and line collide.

## 2.8 Ordering, and why it is visible

A scene's voice jobs are enqueued grouped by voice. This is not an optimisation detail: at
RTF ~1.1 the re-encode is a material share of a scene's wall clock, and the queue's order is
something a user watches in Activity. Grouping is stated here so the order is intentional rather
than incidental.

## 2.9 Licence

IndexTTS 2.5 is released under the bilibili Model Use License Agreement — a worldwide,
non-exclusive, royalty-free grant, with a separate licence required only above 100 M monthly
active users or RMB 1 billion annual revenue. It requires the notice and a copy of the agreement
to travel with any copy of the model, which is a `THIRD-PARTY-NOTICES.md` entry when weights are
fetched, and forbids using the model or its outputs to improve other commercial AI models.

The model card is explicit that it does not verify consent from the speaker in a reference clip.
That is the other half of §1.3's consent tick, and the reason it is required rather than advisory.

## 2.10 Why not Qwen3-TTS

Measured on the same GPU, same clip, same lines: **RTF ~26** through llama.cpp's `llama-tts`
(b10472), with every layer confirmed on CUDA0 — 19× slower than IndexTTS. Everything else favoured
it: Apache 2.0, 10 languages against 5, a 1.4 GB quantised footprint, seven months of maturity, and
a single self-contained CUDA binary needing no Python at all. Its support landed in llama.cpp on
2026-08-04 and the audio path is still flagged experimental.

Worth re-measuring when that implementation matures. If it reaches parity, the packaging argument
favours it strongly enough to revisit this spec's §2.1.

## 3.2 Testing

- `gateLocalRuntimes` disables the row below the floor with both figures and the cloud alternative,
  and reports unknown — still dispatching — when VRAM cannot be measured.
- `previewCacheFile` produces distinct paths for three providers over the same voice id and line
  (the defect T-1 fixes, asserted rather than assumed).
- A cloned voice with no description is refused at creation; one with a description ranks by its
  extracted attributes.
- A voice whose recording artifact is missing reports unusable with the reason and does not
  dispatch.
- The client refuses with the remedy, not an ENOENT, when the engine is not running.
- Delivery mapping covers all six deliveries and produces a vector within the model's ranges.

## 3.3 Definition of done

A character can be given a voice cloned from a clip on this machine, that voice reads their lines
on the bench as a numbered unmetered job, a retake keeps it, and every way the engine can be
not-ready is stated with its measured reason.

## 3.4 Decision log

- **D1** A ComfyUI recipe rather than a runtime of our own or a Voxa engine (§2.1). Revised
  2026-08-19; this previously chose a supervised sidecar, and the packaging cost is why it did not
  survive contact with SPEC-021 D1's reasoning.
- **D2** The cloned-voice library is world-level; the artifact link is provenance, not ownership (§2.3).
- **D3** The description is required, because `rankVoices` sinks attribute-less candidates (§2.3).
- **D4** `use_accel` is never offered; `use_cuda_kernel` is pinned `False` (§2.6).
- **D5** Delivery maps to the emotion vector, not to a second reference clip (§2.5).
- **D6** SPEC-011 §2.3's *local means presets* is retired and replaced per engine (§2.4).
- **D7** Scene voice jobs are ordered by voice, because the conditioning cache holds one (§2.8).

# 1 Requirements

## 1.1 Summary

Finish the two local inference paths Arke has already chosen, and make them read as one coherent
product rather than two pieces of infrastructure the user has to understand.

Arke has two local execution planes because the work has two different shapes:

| Plane | Owns | Why |
|---|---|---|
| **Local speech** | Kokoro preset TTS, whisper.cpp dictation, conversational voice | Small, CPU-capable, latency-sensitive, independently available through Voxa |
| **Local generation** | Curated image, video and cloned-voice recipes | Heavy Python/CUDA work, job-oriented, hardware-gated, run through an Arke-managed or user-directed ComfyUI engine |

ComfyUI is **additional to Voxa**, not a replacement for it. Voxa keeps speech available on a
machine that cannot or should not run the heavyweight generation runtime. ComfyUI gives Arke one
managed Python/CUDA environment, memory manager and fast-moving model-loader ecosystem for work
that has no maintained native runtime. IndexTTS belongs there because it is a heavyweight cloned
voice generator; Kokoro and Whisper remain in Voxa because they do not need Python or CUDA.

That distinction is architectural, not navigational. In the ordinary interface a person enables
**Local voices**, **Dictation**, **Conversational voice**, **Local images**, **Local video** or
**Cloned voices**. They are not asked to select a sidecar, map a models directory, understand a
node graph, or know which process runs a capability. Runtime names, versions, paths, URLs and
verification detail remain available under **Advanced runtime details** for diagnosis and for
people deliberately reusing an existing installation.

This specification completes the paths already present rather than introducing a third local
runtime. It fixes Voxa model setup and readiness, wires the realtime surface SPEC-018 requires,
finishes managed ComfyUI installation and dependency provisioning, completes cloned voice from
capture through an audible take, and gives Settings one authoritative readiness model shared with
pickers and enqueue admission.

## 1.2 Scope

**In scope**

- The durable boundary between the Voxa speech plane and the ComfyUI generation plane.
- Capability-first Settings for local speech and local generation.
- Advanced runtime controls for a selected Voxa executable, an existing ComfyUI path or URL, a
  mapped ComfyUI models directory, and the Arke-managed ComfyUI runtime.
- One-action installation, repair and removal of every Arke-managed dependency a capability needs.
- Independent readiness and degradation for Kokoro, Whisper, conversational voice, image recipes,
  video recipes and cloned-voice recipes.
- Completion of Voxa batch TTS/STT and the SPEC-018 realtime voice transport.
- Completion of the ComfyUI provider, managed runtime lifecycle, recipe verification and recovery.
- Completion of local cloned voice: dependency provisioning, capture, assignment, preview, Bench,
  production takes, delivery, cache, landing, playback and provenance.
- One concrete voice target shape across presets, cloud voices and cloned voices.
- Path confinement, remote-engine disclosure, minimal child environments and runtime cleanup.
- Migration of already persisted voice assignments and cloned-voice records.
- Reconciliation of the stale task lists and contradictory decisions in SPEC-011, SPEC-021 and
  SPEC-022 after this work lands.

**Out of scope**

- Replacing Voxa with ComfyUI for Kokoro or Whisper.
- A general Python inference platform owned by Arke.
- A general ComfyUI graph editor, workflow import, arbitrary nodes, arbitrary samplers or arbitrary
  LoRA paths.
- Installing or modifying arbitrary dependencies inside a user-owned ComfyUI installation without
  an explicit action.
- More than one simultaneously active ComfyUI engine in v1.
- Cloud realtime speech.
- New cloud providers or an ElevenLabs cloning implementation.
- AMD, Intel or Apple managed ComfyUI distributions. Existing user-directed engines may support
  them; the Arke-managed v1 runtime remains the pinned Windows NVIDIA portable build.
- Replacing IndexTTS solely because another model is newer. A model change requires its own measured
  recipe revision and licensing decision.
- Authentication for Arke's renderer-to-coordinator transport, which is a separate application
  boundary from these child runtimes and requires its own security change.

## 1.3 Terms

- **Capability** - the user-facing thing Arke can do, such as Local voices or Cloned voices.
- **Runtime** - a process that performs inference. Voxa and ComfyUI are runtime implementation
  details, visible under Advanced.
- **Engine** - one inference implementation inside a runtime, such as Kokoro, Whisper or IndexTTS.
- **Recipe** - a fixed, versioned, Arke-authored ComfyUI graph and its declared dependencies.
- **Dependency closure** - the runtime, model files, custom nodes and auxiliary files required for
  one capability to become ready.
- **Managed** - acquired, verified, launched, supervised, repaired and removed by Arke.
- **User-directed** - an installation path or URL explicitly chosen by the user. Arke may verify and
  invoke it but does not silently modify it.
- **Interactive speech** - latency-sensitive capture or playback whose cancellation is perceptible
  immediately: dictation, read-aloud and conversational voice.
- **Generated speech** - durable, job-oriented audio such as a cloned character line or Bench take.

## 1.4 Acceptance criteria

### The product surface

- **R-1** The ordinary Settings surface SHALL be organized by user capability, not by runtime
  implementation.
  - **WHEN** a person opens Local runtime **THEN** the primary groups SHALL be **Speech** and
    **Local generation**, not Voxa and ComfyUI.
  - **AND** no ordinary setup step SHALL require knowledge of Python, CUDA packages, ComfyUI nodes,
    graph files, model folder conventions or Voxa command-line arguments.

- **R-2** Speech SHALL show separate rows for **Local voices**, **Dictation** and **Conversational
  voice**, because each can be ready or unavailable independently.
  - **WHEN** Kokoro is unavailable and Whisper is ready **THEN** dictation remains usable and the
    Speech group SHALL NOT collapse both into one failed state.
  - **WHEN** the realtime transport is not ready **THEN** batch dictation and read-aloud SHALL remain
    usable if their own engines are ready.

- **R-3** Local generation SHALL show one row per product capability or shipped recipe, including
  **Local images**, **Local video** and **Cloned voices**, with its state, download size where known,
  hardware requirement, and one next action.
  - **WHEN** a recipe is correctly available but has no voices yet **THEN** it SHALL report
    `no voices`, not unavailable.

- **R-4** A collapsed **Advanced runtime details** section SHALL name the selected runtime source,
  version and safe location, and SHALL contain path, URL, model-folder, restart, re-verify and repair
  controls.
  - **WHEN** a support request needs the engine name **THEN** the information is available without
    making that name part of the ordinary generation workflow.
  - **AND** an absolute Voxa executable path SHALL remain host-owned; renderer state carries at most
    a basename and safe source label.

- **R-5** Enabling an Arke-managed capability SHALL install its complete dependency closure with one
  action and one progress surface.
  - **WHEN** Cloned voices is enabled on a fresh supported machine **THEN** the managed ComfyUI
    runtime, the pinned custom node, its locked Python dependencies and the pinned IndexTTS model
    files SHALL be acquired without sending the user to another Settings group.
  - **AND** completion SHALL automatically resolve, launch and verify the engine; no manual Refresh
    SHALL be required between dependency steps.

- **R-6** Every capability SHALL use the same closed state vocabulary:
  `not-installed`, `downloading`, `installing`, `starting`, `ready`, `needs-attention`,
  `unsupported`, or `unknown`.
  - **WHEN** the state is not ready **THEN** the row states the reason and one remedy.
  - **AND** `unknown` SHALL mean a measurement could not be made, never that a known failure is being
    hidden.

### Voxa: the lightweight speech plane

- **R-7** Voxa SHALL remain a self-contained, architecture-matched .NET child process shipped with
  Arke and SHALL own Kokoro preset synthesis and whisper.cpp transcription.
  - **WHEN** Local generation is absent, unsupported, downloading or failed **THEN** Voxa speech is
    unaffected.
  - **AND** Voxa SHALL accept no cloud provider credentials and SHALL make no cloud speech request.

- **R-8** Kokoro and Whisper readiness SHALL be derived from their individual engine status, not
  from process health or a top-level `ok` field.
  - **WHEN** the HTTP service is healthy but Kokoro failed to load **THEN** Local voices is
    unavailable, Dictation may remain ready, and no Kokoro voice is offered.
  - **AND** provider validation for Kokoro SHALL parse engine readiness rather than treating any
    successful `/health` response as synthesis availability.

- **R-9** Kokoro and Whisper model packages SHALL be optional and independently acquired.
  - **WHEN** the user declines local speech during first run **THEN** neither model downloads.
  - **WHEN** a Kokoro voice is first requested **THEN** only the Kokoro dependency is queued.
  - **WHEN** dictation is first requested **THEN** only Whisper is queued.
  - **AND** every file SHALL be hash-verified before the component becomes ready.

- **R-10** Setup component identities SHALL have one exported definition consumed by setup,
  runtime status, completion-triggered restart, repair and tests.
  - **WHEN** a speech model finishes installation **THEN** Voxa SHALL restart once after setup is
    idle and re-evaluate the affected engine.
  - **WHEN** Repair is pressed **THEN** the files used by the running engine are the files removed,
    downloaded and verified.

- **R-11** Every Voxa request SHALL be bounded and cancellable.
  - **WHEN** health, voices, TTS or STT exceeds its operation-specific deadline **THEN** it ends with
    a typed timeout and the UI leaves its busy state.
  - **AND** all Kokoro synthesis, whether direct or queue-backed, SHALL pass through one
    concurrency-one scheduler so previews, narration and takes cannot overload the engine together.
  - **AND** a restart or shutdown SHALL cancel outstanding requests before the process is replaced.

- **R-12** Voxa SHALL expose the realtime transport required by SPEC-018 and Arke SHALL ship its
  client.
  - **WHEN** voice mode starts **THEN** microphone audio, partial/final transcription, text reply,
    synthesis, barge-in and skip travel through one cancellable session with typed events.
  - **AND** batch `/tts` and `/stt` SHALL remain available for previews, read-aloud and dictation.
  - **AND** the realtime path SHALL implement SPEC-018's gate restrictions; no spoken phrase may
    accept, settle, discard, retire, dispatch or spend.

- **R-13** Voxa SHALL launch with discrete arguments, a minimal allow-listed environment, loopback
  binding and no inherited provider credentials.
  - **WHEN** a configured executable is missing **THEN** the bundled runtime is used with a warning.
  - **AND** a custom model root, if retained, SHALL be used consistently by launch, setup, repair and
    Open folder; otherwise the setting SHALL be removed rather than half-supported.

### ComfyUI: the heavyweight generation plane

- **R-14** Arke SHALL support one selected ComfyUI source at a time: an explicitly selected running
  URL, an explicitly selected portable installation, or the Arke-managed portable runtime.
  - **WHEN** no source is selected **THEN** discovery MAY offer a live default-port engine and known
    installation folders, but SHALL NOT silently adopt or modify one.
  - **AND** detecting an existing installation SHALL NOT remove the option to install the managed
    runtime; only selecting the existing installation does that.

- **R-15** The Arke-managed runtime SHALL be a pinned upstream portable distribution downloaded on
  demand, verified before extraction, installed as one atomic directory and launched under
  `ChildSupervisor` on an allocated loopback port.
  - **WHEN** installation or extraction is interrupted **THEN** no partial directory is considered a
    runtime.
  - **AND** the process SHALL receive a minimal allow-listed environment rather than all of
    Electron's environment.

- **R-16** A fixed Arke recipe SHALL remain the only dispatchable ComfyUI unit.
  - **WHEN** a user generates image, video or cloned speech **THEN** the renderer sees product
    controls and a model row, never a graph, node id, sampler, checkpoint path or workflow import.
  - **AND** provider-call capture and landed media SHALL contain no recoverable graph.

- **R-17** Every managed recipe SHALL declare a complete, immutable dependency closure.
  - **WHEN** a recipe needs a custom node **THEN** that node SHALL be installed from a versioned
    Arke-vendored or digest-pinned archive, not cloned from a moving repository at setup time.
  - **AND** runtime verification SHALL read the archive installer’s sidecar content identity; it
    SHALL NOT require a production Git executable. An unmarked checkout remains unverified.
  - **AND** its Python dependency set SHALL be locked and verified.
  - **AND** every model and auxiliary file SHALL have a source, size and digest known before the
    capability is offered for installation.
  - **AND** a generation request SHALL never trigger an undeclared model or package download from
    inside ComfyUI or a custom node.

- **R-18** Arke SHALL NOT silently modify a user-owned ComfyUI installation.
  - **WHEN** a selected existing installation lacks a required node or dependency **THEN** the recipe
    remains disabled with two explicit remedies: use the Arke-managed runtime, or manage that
    dependency in the existing installation.
  - **AND** Re-verify SHALL measure what is present; it SHALL NOT install or update anything.

- **R-19** Dependency verification SHALL fail closed.
  - **WHEN** a checkpoint, model, auxiliary file or custom node cannot be identified **THEN** the
    recipe is not ready.
  - **WHEN** a custom-node ref cannot be read **THEN** it is unverified, not accepted as matching.
  - **AND** Settings, picker and enqueue admission SHALL consume that same verdict.

- **R-20** A completed runtime, dependency or repair operation SHALL automatically refresh the
  engine and all affected recipes.
  - **WHEN** the managed runtime finishes installing **THEN** it starts without a manual Settings
    visit.
  - **WHEN** weights or a custom node finish installing **THEN** the affected recipe is re-verified
    and moves to ready if every other condition passes.

- **R-21** ComfyUI supervision SHALL cover startup, process exit, hung health and application
  shutdown.
  - **WHEN** a spawned engine exits **THEN** restart follows the bounded supervisor policy and jobs
    follow SPEC-021's recovery decision.
  - **AND** each spawned process SHALL have a distinct opaque epoch, so a restart at the same path
    retires and safely requeues image, video and cloned-voice work from the old in-memory engine.
  - **AND** a terminal startup contract failure SHALL stop immediately without consuming the
    unexpected-exit restart budget.
  - **WHEN** a process remains alive but health fails for the configured window **THEN** it is
    restarted rather than left permanently ready.
  - **WHEN** the coordinator stops or restarts in-process **THEN** subscriptions, timers, sockets and
    the ComfyUI child are disposed before a replacement starts.

- **R-22** Recipe readiness SHALL distinguish total hardware suitability from temporary free-memory
  availability.
  - **WHEN** total VRAM is below the measured floor **THEN** the capability is unsupported and both
    figures are stated.
  - **WHEN** total VRAM is sufficient but too little is free **THEN** the engine is asked to unload
    resident models once, the device is measured again, and refusal names the remaining shortfall.
  - **WHEN** the device cannot be measured **THEN** the state is unknown and dispatch remains
    permitted, per SPEC-021 D15.

- **R-23** ComfyUI work SHALL use the ordinary durable queue, one provider-wide execution lane by
  default, targeted cancellation, local-zero ledger entries and frozen recipe/engine identity.
  - **WHEN** the selected engine changes **THEN** work belonging to the retired engine is resolved
    under SPEC-021's source-specific recovery rule.
  - **AND** source-bound progress sockets SHALL close when that engine retires and at shutdown.
  - **AND** recovered work SHALL wait for a spawned engine to become ready before it is pumped.

### Voice identity and cloned-voice completion

- **R-24** Every selected voice SHALL resolve to a concrete voice target containing
  `{provider, model, voiceId}`.
  - **WHEN** more than one TTS model exists behind a provider **THEN** assignment, preview, estimate
    and generation SHALL still select the same model.
  - **AND** existing assignments containing only `{provider, voiceId}` SHALL resolve through a
    versioned migration map for the currently shipped Kokoro, ElevenLabs and ComfyUI models and be
    written in the concrete form on the next sheet change.

- **R-25** The unified voice catalogue SHALL declare behavior rather than requiring provider-name
  branches: local or remote execution, preset or cloned source, supported uses, cloning support,
  delivery support, format, price and readiness.
  - **WHEN** a new TTS provider is added **THEN** preview, narrator, assignment and take generation
    SHALL NOT need an `if provider ==` branch merely to classify it as local, queued or playable.

- **R-26** A cloned voice SHALL complete every surface on which it is offered.
  - **WHEN** it appears in the character picker **THEN** it can be assigned.
  - **WHEN** it is assigned **THEN** candidate preview, Bench generation and production voice-line
    generation resolve the same source clip and model.
  - **AND** a missing source clip refuses before enqueue with the remedy.
  - **AND** a narrator picker SHALL either filter it out with a declared unsupported use or support
    it end to end; it SHALL NOT persist a choice read-aloud later rejects.

- **R-27** A cloned-voice source clip SHALL remain world-relative and confined.
  - **WHEN** a hand-edited or imported library contains an absolute path, traversal, alternate data
    stream, symlink escape, directory, unsupported format or oversized file **THEN** the clip is
    refused before any provider call.
  - **AND** no absolute world path SHALL enter a job journal, renderer frame, diagnostic record or
    provider-call record.
  - **AND** the engine upload name SHALL be content-addressed or job-unique so two worlds cannot
    overwrite each other's reference clip.

- **R-28** Generated speech SHALL have one format contract from recipe through playback.
  - **WHEN** a recipe declares WAV **THEN** the save node, provider metadata, verifier, sanitizer,
    cache extension, media server and player SHALL all use WAV.
  - **AND** audio verification SHALL check the complete container structure needed for safe playback,
    not only a prefix.

- **R-29** Delivery support SHALL be declared by the concrete model or recipe and consumed by every
  generation surface.
  - **WHEN** a delivery is supported **THEN** the production dialog and Bench send the same validated
    provider parameters.
  - **WHEN** it is unsupported **THEN** the UI states that before enqueue.
  - **AND** IndexTTS SHALL expose only controls measured to produce an audible result; the spec SHALL
    be amended if the full emotion vector remains deliberately unwired.

- **R-30** Preview cache identity and result events SHALL carry the actual provider, model, voice,
  normalized text, format, settings version and delivery parameters.
  - **WHEN** the same voice id exists under two providers or models **THEN** their selection state,
    cache files and result events cannot collide.
  - **AND** a completed ComfyUI preview replays without another generation.

- **R-31** Cloning provenance SHALL be transactional from the product's point of view.
  - **WHEN** artifact filing fails **THEN** clone creation fails and no catalogue entry is published.
  - **AND** consent remains required at both UI and command-schema boundaries.
  - **AND** the choice to retain a voice-owned copy after its provenance artifact is deleted SHALL be
    recorded as the authoritative behavior in SPEC-022.

### Cloud voice and routing

- **R-32** Cloud synthesis SHALL continue to use the ordinary queue; neither Voxa nor ComfyUI SHALL
  receive a cloud provider credential.
  - **WHEN** ElevenLabs synthesis succeeds synchronously **THEN** its bytes are made durable before a
    recoverable remote job state is recorded.
  - **AND** an interrupted submit follows the real provider declaration; tests SHALL NOT claim
    idempotency the client does not support.

- **R-33** A cloud provider key SHALL be displayed as `stored, not tested` until its capability probe
  succeeds.
  - **WHEN** a key is invalid, exhausted, unauthorized for TTS, faulted or its model is switched off
    **THEN** no voice catalogue or enqueue path treats it as usable.
  - **AND** cloud cloning SHALL not be advertised until a provider-specific clone operation exists.

- **R-34** The global `voice-tts` row SHALL be removed from **Who does what** unless it is given
  concrete semantics consumed by voice planning.
  - Character voice identity is selected on the sheet, narration by the narrator preference and a
    Bench voice per take; a default that affects none of them is not a setting.

### One readiness answer and durable settings

- **R-35** One authoritative eligibility function SHALL answer whether a concrete local or cloud
  model can execute now.
  - It SHALL combine manifest membership, model switch, credential/probe/fault state, runtime state,
    recipe dependency verification, hardware readiness and supported use.
  - Settings, catalogues, pickers, routing writes and enqueue admission SHALL consume it rather than
    reconstructing subsets of the rule.

- **R-36** App settings and credential mutations SHALL be serialized per backing file.
  - **WHEN** two independent controls are changed concurrently **THEN** both changes survive.
  - **WHEN** a settings file is malformed **THEN** the file is preserved or quarantined, independently
    valid blocks are recovered where possible, and Settings reports repair; the next write SHALL NOT
    silently replace the entire file with defaults.
  - **AND** credential writes SHALL use unique temporary files and treat required ACL hardening as
    part of successful persistence.

- **R-37** A user-directed non-loopback ComfyUI URL SHALL be classified as remote wherever data
  locality is shown.
  - **WHEN** a cloned-voice reference would be uploaded for the first time to that engine **THEN**
    Arke names the destination and requires explicit confirmation.
  - **AND** no row backed by that engine SHALL say `on this machine`.

## 1.5 Open questions

- Whether an existing ComfyUI installation should ever receive an Arke-vendored custom node through
  an explicit action. v1 says no: use the managed runtime or let the owner manage their install.
- Whether the managed runtime should move from the upstream NVIDIA portable archive to one
  Arke-produced archive. Keep upstream while its pinned artifact is adequate; revisit only if the
  dependency closure cannot be installed and verified without mutating it after extraction.
- Whether a cloned voice should support long-form narration in v1. The catalogue's supported-use
  field makes either answer honest; do not offer it until chunking, cache and queue behavior are
  implemented.
- Whether IndexTTS remains the default cloned engine after comparison with Qwen3-TTS, LuxTTS and
  Chatterbox. This spec completes the selected recipe; changing the model requires measured quality,
  hardware, license and packaging evidence.
- Whether Voxa's realtime protocol extends protocol 1 compatibly or becomes protocol 2. Choose from
  a wire-compatibility review; do not add fields that make the strict existing client reject health.

# 2 Design

## 2.1 Architectural decision

**Two execution planes, one capability surface.**

```text
Arke Studio
  |
  +-- Speech
  |     +-- Local voices -------- Voxa / Kokoro
  |     +-- Dictation ----------- Voxa / whisper.cpp
  |     `-- Conversational voice  Voxa realtime pipeline
  |
  `-- Local generation
        +-- Images -------------- fixed ComfyUI recipes
        +-- Video --------------- fixed ComfyUI recipes
        `-- Cloned voices ------- fixed ComfyUI / IndexTTS recipe
```

The boundary follows operational behavior rather than media type. Voxa handles small models that
run on CPU and serve interaction. ComfyUI handles large Python/CUDA models that produce durable
jobs and compete for GPU memory. A video render cannot strand dictation or a spoken reply; a failed
speech sidecar cannot stop an image job.

This is also why the existence of Kokoro nodes for ComfyUI does not collapse the architecture.
Being executable in a graph does not make a 2 GB download and 6 GB Python/CUDA installation the
right prerequisite for a 93 MB CPU voice model. Conversely, IndexTTS already needs Python, PyTorch,
CUDA-aware memory handling and a model loader. Running it as a curated recipe reuses costs Arke has
accepted for image and video.

## 2.2 What Voicebox proves, and what Arke keeps

Voicebox demonstrates that a desktop application can package a Python FastAPI backend and hide
Kokoro, Whisper and several cloned-voice engines behind one native-looking product. That establishes
feasibility; it does not make that architecture free.

Its implementation also demonstrates the standing cost: one broad dependency environment, model
packages installed around conflicting declared dependencies, extensive PyInstaller hooks, separate
CPU/CUDA/ROCm artifacts, shared native failure state and a model registry that must keep pace with
every engine. Arke does not need that breadth to finish its current product.

Arke keeps the parts of its architecture that are already stronger:

- the durable queue remains authoritative rather than moving into an inference server;
- exact recipe and dependency identity are frozen into jobs;
- consent is required by the command schema, not only by UI copy;
- lightweight speech remains independently available;
- a managed generation runtime is one curated backend, not a public plugin surface;
- existing ComfyUI installations can be reused without forcing every user to maintain one.

The decision can be reopened if local voice becomes a product of its own and measured evidence shows
that a dedicated speech runtime materially improves model choice, quality or support cost. In that
case the replacement must subsume Voxa and ComfyUI-for-voice together; adding a third permanent
speech path is not an acceptable intermediate architecture.

## 2.3 Settings is a capability projection

The Settings page is not the source of runtime truth. It projects a readiness graph assembled by
the coordinator:

```text
capability
  -> concrete model or recipe
  -> selected runtime source
  -> runtime compatibility
  -> dependency closure
  -> hardware gate
  -> provider credential/probe, where cloud
  -> ready or one named refusal
```

The primary page shows the first failing node and its remedy. Advanced details show every node.
This removes three current contradictions:

1. a generic local-model hardware row calling a model ready while its runtime is absent;
2. Who does what accepting a local recipe whose dependency readiness is disabled;
3. a provider pane calling an untested key connected while the generation picker has less evidence.

### Primary layout

```text
LOCAL

Speech
  Local voices          Ready                         Test
  Dictation             Not installed - 141 MB       Download
  Conversational voice  Needs Dictation              Set up

Local generation
  Images                Ready
  Video                 Needs 8 GB VRAM; has 4 GB     Unsupported
  Cloned voices         Not installed - 10.2 GB      Download

Advanced runtime details                                  >
```

Cloud voice remains under Providers because its defining setup is a credential and a billing
relationship, not a local runtime.

### Advanced layout

Advanced names the machinery transparently:

- **Speech engine: Voxa** - bundled/configured/environment source, version, architecture, restart,
  model folder, repair and executable selection.
- **Local generation engine: ComfyUI** - Arke-managed/existing path/existing URL, version, safe
  location, models mapping, restart, refresh and per-recipe verification.
- **Use an existing installation** - detected offers and host-owned folder selection.
- **Connect to a running engine** - URL, explicitly marked local or remote.

Names are hidden from the ordinary decision, not from diagnostics. This is abstraction rather than
obscurity.

## 2.4 Activation is a dependency transaction

A capability is enabled as one logical operation even when several components install underneath.
The operation computes its dependency closure before downloading and shows total transfer, peak disk
requirement and hardware compatibility first.

For Cloned voices that closure is at least:

```text
managed ComfyUI runtime, unless a selected existing engine is compatible
  + vendored TTS-Audio-Suite node and locked dependencies
  + IndexTTS model files and auxiliaries
  + recipe verification
```

Each component retains independent atomic installation and repair, but the UI follows the whole
activation until the capability is ready or one step fails. Setup completion invokes the runtime
resolver; it does not wait for a manual Refresh.

Detection is an offer, not a decision. Finding `C:\AI\ComfyUI` does not silently bind Arke to it and
does not suppress the managed Download action. This matters most for cloned voice: a vanilla
existing installation may run core image/video recipes and lack the pinned voice node. The managed
runtime is the zero-configuration answer.

## 2.5 Voxa completion

Voxa remains deliberately small. Its Arke profile exposes local speech only and owns no provider
key, cloud client, world path or durable job state.

Batch requests remain appropriate for:

- short voice previews;
- read-aloud chunks;
- push-to-talk dictation;
- Kokoro queue jobs that need an immutable take.

The realtime session is separate because it has different lifecycle semantics. It must carry an
open microphone session, partial and final transcripts, spoken response chunks, interruption and
session termination. SPEC-018 remains authoritative for what voice mode may do; this spec owns
making the transport real and bounded.

One process-level Kokoro scheduler covers every caller. Per-method sequencing is insufficient: two
previews, narration and a queue job are independent requests to Arke but the same model to Voxa.
Timeouts are operation-specific and return typed failures so UI state always terminates.

Health keeps service liveness distinct from engine readiness. `ok: true` means the protocol host is
alive; it never means Kokoro and Whisper are both ready. Settings, provider availability and feature
gates read the engine statuses directly.

## 2.6 ComfyUI completion

The managed ComfyUI runtime is an implementation dependency, not a second application surface.
Arke launches the portable build with metadata disabled, a generated model-path mapping where
needed, a dynamic loopback port and a minimal environment. The graph editor is never opened by the
normal product flow.

Recipes remain immutable values compiled into the provider package. A recipe identity covers:

- recipe version;
- canonical graph digest;
- checkpoint and auxiliary file digests;
- custom-node source/content digest;
- declared input and output formats;
- hardware floor and evidence source.

The IndexTTS recipe's current delegated model download is retired. A node may read its model from an
Arke-managed verified cache, but it may not fetch code or model data during generation. Offline
dispatch after setup is a test requirement.

Managed custom nodes are installed beside the managed engine from immutable archives. Existing
installations are measured but not altered. This deliberately gives the two source types different
responsibilities while keeping the recipe result the same.

## 2.7 Voice identity is concrete

`{provider, voiceId}` was sufficient while each provider exposed one TTS model. It is not sufficient
for a recipe catalogue or a provider with multiple speech models. The durable target becomes:

```yaml
provider: comfyui
model: comfyui-cloned-voice
voiceId: harbour-glass
```

The assignment identifies who speaks and how that identity is rendered. Delivery remains a take
property. The voice library remains independent of assignment: its recording can be rendered by a
future compatible model without silently changing existing assignments.

The catalogue describes supported uses. For example:

| Voice source | Preview | Character line | Bench | Narration | Realtime |
|---|---:|---:|---:|---:|---:|
| Kokoro preset | yes | yes | yes | yes | yes |
| ElevenLabs catalogue | yes | yes | yes | yes, confirmed | no |
| IndexTTS clone | yes | yes | yes | only when implemented | no |

The table is data, not a provider-name switch. A picker filters by its requested use and therefore
cannot save a choice the subsequent operation rejects.

## 2.8 Local cloned voice, end to end

One resolver owns the path from a voice target to executable inputs:

```text
voice target + world
  -> catalogue entry
  -> model/recipe readiness
  -> confined source clip
  -> provider parameters
  -> estimate and cache identity
```

Assignment, preview, Bench and production call that resolver. None reconstructs the relationship
between `comfyui` and a clip itself. The resolved clip is read as a host-owned ephemeral input, like
an image reference, rather than persisted as an absolute path in job parameters.

The output contract is WAV in v1. It is widely playable, already served by Arke, and allows a
bounded sanitizer/verifier. If the engine only emits FLAC, the recipe adds an explicit local
conversion step before returning the artifact; every downstream contract still sees WAV.

## 2.9 Existing and remote ComfyUI

Existing-install support is an optimization for people who already have a model library, not a
prerequisite placed on everyone else.

- A portable path selected by the user is launched and supervised by Arke.
- A source/venv installation that Arke cannot launch is offered only as a URL after the user starts
  it; Settings states that distinction before selection.
- A URL is never spawned or modified.
- A URL without a local models-directory mapping cannot satisfy digest verification for recipes
  with local files.
- A non-loopback URL is remote. Any voice clip upload requires destination-specific confirmation.

Only one engine is active in v1. Choosing an existing engine is therefore a deliberate replacement
of the managed source, not an automatic preference inferred from a process answering on port 8188.

## 2.10 Lifecycle and recovery

Arke's queue remains the owner of durable work. Neither runtime owns business identity, world paths,
take numbers, billing records or retry policy.

Voxa batch operations are synchronous local calls and must either return bytes or fail within their
deadline. ComfyUI operations remain asynchronous jobs with frozen engine and recipe identity.

Spawned ComfyUI recovery waits for readiness before requeue. A surviving URL engine may be polled
only when the selected source identity still matches. A changed source never receives an old prompt
id. Process exit, hung health and explicit Settings changes all use the same retirement path.

## 2.11 Security and privacy

- Child processes receive allow-listed environments and no provider keys.
- Voxa accepts only loopback and no cloud configuration.
- Managed ComfyUI accepts only loopback and metadata writing is disabled.
- User URLs are classified by actual destination, not by the provider's nominal `local` flag.
- Reference clips are validated and confined before reading.
- Uploaded clip names reveal no world, character or local path and cannot collide.
- Provider capture stores recipe identity and safe counts, never graph, text, clip bytes or path.
- Dictation audio is discarded after transcription and its transcript is not copied into a global
  operational log merely because it arrived as an event.

## 2.12 Migration and compatibility

Persisted worlds and settings are a concrete compatibility requirement.

- Existing `{provider: "kokoro", voiceId}` assignments migrate to model `kokoro-82m`.
- Existing `{provider: "elevenlabs", voiceId}` assignments migrate to model
  `eleven_multilingual_v2`.
- Existing `{provider: "comfyui", voiceId}` assignments migrate to model
  `comfyui-cloned-voice` only when that voice id exists in the world's cloned library.
- An assignment that cannot be migrated remains visible and unavailable with a reason; it is never
  silently replaced by another voice.
- Existing ComfyUI path, URL and models-folder settings remain valid and move under Advanced without
  changing their precedence.
- Existing preview cache files may be reused only when their complete provider/model/format identity
  can be proven; otherwise they are ordinary disposable cache misses.

## 3.2 Testing

**Capability Settings** - a fresh install can enable each capability from its own row and reaches
ready without changing tabs or pressing Refresh. Engine names appear only in Advanced. Every state
has one reason and one valid action. A detected existing ComfyUI is offered but not adopted, modified
or allowed to suppress the managed option.

**Voxa matrix** - test service alive with each engine independently ready/down; absent, downloading,
verification-failed and incompatible states; first-use download of only the requested model;
completion restart using real catalogue IDs; Repair replacing the files launch actually reads.

**Voxa lifecycle** - hung health/TTS/STT requests time out; killed mid-request reports failure and
restarts; concurrent preview, narration and queue requests never overlap inference; shutdown leaves
no process or pending request. The packaged smoke runs real Kokoro and Whisper inference.

**Realtime voice** - partials precede the final, release sends, a measured silence boundary ends an
open-session turn, barge-in cancels playback within the stated frame budget, skip leaves written
text, and leaving the surface closes capture. The SPEC-018 forbidden-action suite attempts every
gated or spending command by voice.

**Managed generation setup** - a clean supported machine downloads the pinned runtime, custom node,
locked dependencies and recipe files atomically; every digest is checked; no generation-time network
fetch occurs; interrupted setup resumes or repairs without recognizing partial state.

**Existing engines** - selected portable installs are supervised; source installs give the URL
remedy before adoption; URL engines are never spawned; no existing install is modified; missing
dependencies disable only affected recipes; changing source resolves old jobs under the frozen
identity policy.

**Cloned voice end to end** - record/import, consent, clone, assign, preview, cache hit, Bench take,
production take, retake with delivery and playback all succeed against the managed runtime. Missing
clips refuse before enqueue. The same voice id under multiple providers cannot collide.

**Audio contract** - the actual recipe output passes sanitizer and structural verification, lands
atomically, serves with the right MIME type and plays. Truncated or mislabeled WAV/FLAC/MP3 is
refused. Output contains no graph or workflow metadata.

**Path and privacy** - absolute, traversal, UNC, alternate-stream, symlink, directory, replacement
race, oversized and wrong-magic clips are refused. No absolute world path appears in jobs, snapshots,
logs or captures. A non-loopback engine cannot receive a clip before destination confirmation.

**Eligibility parity** - table-driven tests feed every combination of credential state, probe,
fault, model switch, runtime, recipe, hardware and requested use through Settings, picker and enqueue;
all three return the same answer and reason.

**Crash and recovery** - kill at each managed ComfyUI state, including accepted-before-id-recorded,
running, fetching, landed-before-finalized and engine restart. No work is silently duplicated or
lost. Kill after ElevenLabs returns bytes and prove the paid artifact survives.

**Persistence** - concurrent independent settings and credential writes preserve every field;
malformed blocks preserve valid runtime configuration and produce a repair state; required ACL
failure fails the credential transaction.

## 3.4 Decision log

| # | Decision | Rationale |
|---|---|---|
| D1 | Keep two local execution planes | Lightweight interactive speech and heavyweight job-oriented generation have different latency, hardware and failure requirements. A video render must not strand dictation. |
| D2 | ComfyUI is additional to Voxa | It adds cloned voice and generated media; it does not replace the CPU-capable Kokoro/Whisper baseline. |
| D3 | Settings leads with capabilities and puts engines under Advanced | Users need to decide what Arke may install and do, not how an internal process spells its command line. Engine identity remains visible for support. |
| D4 | Managed ComfyUI is the zero-configuration path | Arke already pins, downloads and supervises the upstream portable runtime. Completing that path is less standing maintenance than assembling another Python/CUDA platform. |
| D5 | Existing ComfyUI is explicit reuse, never silent adoption or modification | A user's curated engine and model library are valuable and fragile. Detection offers; selection authorizes use; only a separate explicit future decision could authorize modification. |
| D6 | Activation installs a complete dependency closure | A runtime reported ready while its node or 10 GB model is missing is not ready. One capability needs one operation and one terminal answer. |
| D7 | Voxa remains the realtime speech host | It already owns typed frames, cancellation, backpressure and interruption. ComfyUI's graph queue is the wrong scheduling domain for microphone turns and barge-in. |
| D8 | The durable voice target includes the model | Provider plus voice id becomes ambiguous as soon as one provider has two TTS models. Persisting the concrete model makes previews, delivery and takes reproducible. |
| D9 | Voice has no global routing default | Character assignment, narrator preference and per-take Bench choice already own the decision. A control no planner reads is removed rather than rationalized. |
| D10 | Managed custom nodes are vendored or digest-pinned; existing installs are only verified | Code executing on the user's machine cannot come from a moving repository during setup, and Arke does not mutate user-owned environments silently. |
| D11 | Generation never downloads dependencies | Setup owns progress, integrity, disk checks, license notice and repair. A job is not an installer with an indeterminate wait hidden inside it. |
| D12 | One ComfyUI engine is active in v1 | Per-recipe engine routing and multiple GPU processes add scheduling and recovery complexity before evidence requires it. The selected source must satisfy every recipe it offers. |
| D13 | Remote is a property of the selected engine, not the provider id | A `comfyui` row can execute on loopback or another machine. Biometric upload copy must reflect the actual destination. |
| D14 | Voicebox validates feasibility, not the immediate architecture | A packaged Python speech platform can work, but its dependency, platform and model-maintenance cost is real. Revisit only if voice breadth becomes strategic enough to replace both current voice paths. |
| D15 | Arke's queue remains authoritative | Runtime processes execute inference. They do not own world identity, retries, take creation, cost, provenance or recovery policy. |
